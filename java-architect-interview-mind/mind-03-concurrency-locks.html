① 内存语义与同步原语 · 章节题 + 八股

C03.01 volatile 如何保证可见性、为何不保证原子性
volatile 通过在其周围插入内存屏障（写-StoreStore/StoreLoad、读-LoadLoad/LoadStore）保证读取总是取主内存最新值并禁止重排；但它不提供复合操作原子性，count++ 仍是读-改-写三步，多线程自增会丢更新，须用原子类/锁。
章节volatile内存屏障
C03.02 synchronized 的锁升级过程
无锁→偏向锁（同线程重入免同步，JDK15 默认废弃）→轻量级锁（CAS 自旋，多线程竞争小）→重量级锁（互斥量，OS 调度）。升级由 Mark Word 低位状态 + 竞争程度驱动。JDK 强调锁消除/偏向字段重排，回答要落到 Mark Word 位图。
章节锁升级Mark Word
C03.03 AQS 的 CLH 队列与 CAS 如何实现同步
AQS 以 volatile state + FIFO CLH 变体队列为骨架：获取同步节点入队，CAS 改 state；释放时唤醒后继。独占（ReentrantLock 用 lock/unlock 模板）与共享（Semaphore/CountDownLatch）两模式。核心是"状态 + 队列 + 模板方法"三件套。
章节AQSCLH
C03.04 CAS 与 ABA 问题如何解决
CAS 用 Unsafe.compareAndSwap 原子比较并交换，失败重试；ABA＝中间被改回原值被误判成功。解法：AtomicStampedReference/AtomicMarkableReference 加版本号；业务上"值不重要、关键在终态"时 ABA 未必有害，需按一致性要求取舍。
章节CASABA
C03.05 ReentrantLock 与 synchronized 如何选择
都需要可重入；ReentrantLock 提供公平锁、可中断、超时、多 Condition 精确唤醒；synchronized 由 JVM 优化升级更简洁、异常自动释放。默认选 synchronized；需超时/中断/多条件时切 ReentrantLock。答要讲"场景驱动"而非背差异。
章节ReentrantLock

② 并发容器与等待通知 · 章节题 + 八股

C03.06 ConcurrentHashMap 并发安全如何保证
JDK8 以 Node + CAS + synchronized（锁桶头）替代 JDK7 Segment；get 无锁读、put 全程线程安全、扩容并发分段迁移（forwarding node + helpTransfer）。读多写少高效；复合操作仍需外层原子封装。与八股 E03.01 演进视角互通。
章节CHM桶锁
C03.07 Condition 与 LockSupport 等待/通知
Condition 绑定 ReentrantLock 提供 await/signal 的精确唤醒队列（比 wait/notifyAll 细粒度）；LockSupport.park/unpark 可直接阻塞/唤醒任意线程（底层 Unsafe），是 AQS 挂起机制基础。答：唤醒粒度与失联场景是进阶分水岭。
章节ConditionLockSupport
C03.08 Java 并发集合与各自场景
CopyOnWrite(读多写少)、ConcurrentHashMap、ConcurrentLinkedQueue、BlockingQueue 族（Array/Linked/Synchronous/Delay/Priority）、ConcurrentSkipListMap。选型按读写比、有序、阻塞需求分档；答用"数据结构 + 保证维度"收敛。
章节并发集合

③ 高性能与 OS 模型 · 章节题

C03.09 ForkJoin 分治与工作窃取
ForkJoin 把任务拆到足够细再 join 聚合，双端队列 + 工作窃取（空闲线程从别队尾偷任务）摊薄负载；适合递归分治（快排、归并、并行流底层）。避免拆分过细导致队列开销>计算。
章节ForkJoin工作窃取
C03.10 线程安全计数器
低竞争用 AtomicInteger（CAS）；高并发累加用 LongAdder（分段 cell 摊薄热点，sum 汇总求得近似）；需要版本语义用 AtomicStampedReference。扩展到无锁数据结构与聚合场景均适用。
章节LongAdder计数器
C03.11 Disruptor 无锁队列原理
环形缓冲区预分配避免 GC + 序号 Sequence 配合内存屏障（缓存行填充防伪共享）实现无锁单/多生产者消费者；用 CAS 与屏障数组交换状态而非互斥锁。适合超高频事件；权衡是复杂度与调试成本。
章节Disruptor环形缓冲
C03.12 用户态/内核态线程模型
OS 线程 1:1 内核映射，上下文切换进内核、成本高；Java 平台线程即 OS 线程；虚拟线程由 JVM 调度挂载到少数平台线程，阻塞自动卸载，把"阻塞式编程"带回高并发。答对比用户线程/协程、切换代价、pinning。
章节线程模型OS/内核
