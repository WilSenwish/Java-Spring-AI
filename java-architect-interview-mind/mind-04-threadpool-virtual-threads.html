① 线程池治理 · 章节题 + 原理

C04.01 线程池 7 参数调优与拒绝策略
核心/最大线程数、空闲存活、时间单位、任务队列、线程工厂、拒绝策略五选（Abort/Discard/DiscardOldest/CallerRuns/自定义）。核心公式：core≈CPU×N；IO 密集可调大；队列用有界+饱和策略兜底，避免无界吞任务。拒绝用 CallerRuns 降速保削峰。
章节7参数拒绝策略
C04.02 线程池工作流程与状态流转
提交→核心线程满则入队、队列满才扩到最大、再满走拒绝。状态 RUNNING→SHUTDOWN（不再收新任务）→STOP→TIDYING→TERMINATED。答流程要呈现"核心→队列→最大→拒绝"四级演进与优雅关闭 shutdown/awaitTermination。
章节状态机
C04.03 ThreadLocal 为何内存泄漏、如何避免
ThreadLocalMap 的 Entry 用 ThreadLocal 弱引用作 key，value 强引用残留于存活线程导致泄漏（尤其线程池复用线程）。避免：主动 remove（finally）、线程池用后清理、避免大对象、InheritableThreadLocal 在池化场景要慎用。配 TransmittableThreadLocal 做跨上下文透传。
章节ThreadLocal弱引用
C04.06 CompletableFuture 如何编排异步任务
thenApply/thenCompose（依赖）、thenCombine/allOf（聚合）、exceptionally/handle（异常兜底）、supplyAsync(线程池) 控制执行池。避免回调地狱与线程池放大（Async 版单独指定池），用超时+取消防悬挂。构建可读的异步 DAG。
章节CompletableFuture

② 虚拟线程革命 · 章节题 + 原理 + 场景

C04.04 Virtual Threads 如何重构并发模型
JVM 级纤程，由虚拟线程调度器挂载到少量平台线程，阻塞 IO 时自动卸载，一个平台线程可承载数十万 VT。核心收益：百万级并发会话、代码仍是顺序阻塞风格。注意：synchronized/native 会 pinning、CPU 密集任务慎用 VT（无卸载收益）。
章节Virtual Threads
C04.05 Virtual Threads 在 Spring Boot 落地
`spring.threads.virtual.enabled=true` 让 Tomcat 用虚拟线程处理请求；配合 `-Djdk.tracePinnedThreads=full` 排查 pinning。收益立竿见影（连接数不再卡在平台线程上限）；限制是 JDBC 阻塞与外部阻塞也要能卸载，纯 CPU 与锁竞争无收益。
章节Spring Boot
C04.09 虚拟线程 pinning 排查与治理
pinning＝VT 在 synchronized 或 native 方法中无法卸载，钉死平台线程。定位用 JFR VT 事件 + tracePinnedThreads；治理：避免 synchronized 保护阻塞点、换 ReentrantLock、减少 native 调用、控制单平台线程上的 pinning 路径。是 VT 生产核心坑。
章节pinning
C04.10 ScopedValue 安全传递上下文
JEP 429，作用域继承，快于 ThreadLocal 且不可变、避免"跨任务误传"，受限范围自动清理。在 VT 时代替代 ThreadLocal 传 TraceId/用户态更安全。答要点：绑定作用域与可变性的取舍，是上下文传递的新范式。
章节ScopedValueJEP429

③ 并发设计范式 · 章节题

C04.07 响应式 vs 传统 Servlet 本质差异
Servlet=阻塞+每请求一线程；WebFlux=事件驱动+少量线程承载海量并发，带来背压与组合式 API，但调试复杂、心智成本高。选型看 IO 密集度与团队。呼应 C15 响应式章双入口。
章节WebFlux
C04.08 Structured Concurrency 管理并发任务
JEP 453 结构化并发把子任务视为一个作用域单元，整体失败/超时统一取消，避免线程孤儿化。用 StructuredTaskScope 聚合并行子任务，成功/失败/取消语义清晰。是"任务归属"思维的工程化表达。
章节结构化并发

场景 S06.01 Java 21 虚拟线程落地：高并发网关迁移
网关从平台线程迁 VT：开开关、削连接数上限、查 pinning（避免业务代码 synchronized 阻塞 IO）、配合线程池改虚拟线程执行；验收以压测对比线程数与 P99。是"VT 收益+坑"的完整样板。
