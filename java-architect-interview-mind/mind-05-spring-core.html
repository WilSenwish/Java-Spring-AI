主题卡详情

① 容器与生命周期 · 章节题 + 八股

C05.01 Spring IoC 启动流程与 Bean 生命周期
启动：配置加载→扫描/解析 BeanDefinition→注册→实例化→属性填充→初始化（Aware+@PostConstruct+InitializingBean）→就绪→销毁。生命周期口诀"实例化→初始化→使用→销毁"，结合单例池与作用域。
章节IoC生命周期
C05.02 三级缓存如何解决循环依赖、为何需要三级
singletonObjects(成品)→earlySingletonObjects(半成品)→singletonFactories(工厂)。核心是"暴露早期引用 + 提前 to AOP"，AOP 代理需在早期暴露时完成故用工厂三级。构造器循环依赖与 prototype 无法解决。
章节三级缓存循环依赖
C05.07 BeanPostProcessor 与 BeanFactoryPostProcessor 区别
前者作用于 Bean 实例（postProcessBefore/AfterInitialization），可包装代理；后者作用于 BeanDefinition（改属性/作用域），执行更早。二者共同构成 Spring 最核心扩展点，自定义 Starter 常搭配使用。
章节扩展点PostProcessor
C05.08 BeanFactory 与 ApplicationContext 的区别
BeanFactory 是最基础容器（延迟加载、依赖注入最小）；ApplicationContext 是其子接口，补齐事件、国际化、资源加载、AOP 自动注册与环境的便利能力，是企业应用默认选择。
章节容器层级

② AOP 与事务 · 章节题 + 八股

C05.03 Spring AOP 的 JDK 动态代理与 CGLIB 如何选择
JDK 动态代理要求目标实现接口，基于 Proxy+InvocationHandler；CGLIB 通过继承生成子类，无需接口但 final 方法无法代理。Spring 默认按"有接口优先 JDK、否则 CGLIB"，boot2.x 起默认 CGLIB。答要点：两者字节码差异 + 代理失效场景。
章节动态代理
C05.04 @Transactional 的 7 种传播行为与失效场景
REQUIRED/SUPPORTS/MANDATORY/REQUIRES_NEW/NOT_SUPPORTED/NEVER/NESTED。失效高频：自调用(this)、非 public、异常被 catch、代理未织入、DB 引擎不支持事务。传播选型要结合嵌套边界与性能。
章节事务传播
C05.05 Spring 事件机制原理
ApplicationEvent 发布→ApplicationEventPublisher→按 listener 分发，默认同步，可 @Async 异步或事务绑定（@TransactionalEventListener）。是可观测与解耦的轻量手段，注意异步回滚与监听器异常隔离。
章节事件机制

③ 表达与扩展 · 章节题 + 八股

C05.06 Spring 中用到了哪些设计模式
工厂(BeanFactory)、单例(默认容器)、代理(AOP)、模板方法(JdbcTemplate/RestTemplate)、观察者(事件)、适配器(HandlerAdapter)、策略、责任链(过滤器)。把框架当"设计模式集合"来谈，展示抽象提炼能力。
章节设计模式
C05.09 Spring 类型转换与数据绑定机制
PropertyEditor 旧内核 / ConversionService 新内核 + Converter/Formatter 注册、@DateTimeFormat/@NumberFormat 注解绑定。用于 MVC 参数、@Value、配置绑定（@ConfigurationProperties）等场景，强调"字符串→对象"的 SPI 通道。
章节类型转换
C05.10 SpEL 表达式语言原理与应用
Parser→AST→EvaluationContext 缓存求值，支持属性访问、方法调用、条件运算与安全导航。应用在 @Value("${...}")、@Cacheable key、Spring 事件/安全注解表达式、自定义规则引擎中。
章节SpEL

② 八股并入党：IoC/AOP/事务速记 · 八股文

八股 E04.01 Spring 循环依赖：三级缓存源码级解析与局限
三级缓存各司其职；singletonFactories 用于早期暴露+AOP 提前；局限：构造器循环、prototype、@Async 代理等无法/难解决。与 C05.02 完全同题双入口。
八股循环依赖
八股 E04.04 Spring 事务：传播/隔离/失效/@Transactional 底层
底层 TransactionInterceptor+PlatformTransactionManager；传播 7 种、隔离 4 种（对应 DB）；失效场景同 C05.04；编程式事务兜底复杂回滚。与 C05.04 同题。
八股事务
八股 E04.06 Spring AOP 原理与动态代理失效场景
AOP 靠代理织入 Advisor 链；JDK/CGLIB 差异见 C05.03；自调用、final、类内部方法导致的代理失效是高频考点。与 C05.03 同题。
八股AOP
八股 E01.03 常用设计模式：策略/工厂/观察者/责任链/模板
每个模式讲"定义→本质→Spring 中的落点"；策略(FunctionController/Handler)、工厂(BeanFactory)、责任链(Filter/Interceptor)、模板(JdbcTemplate)。与 C05.06 相互印证。
