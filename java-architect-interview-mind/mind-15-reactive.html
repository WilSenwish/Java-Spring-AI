① 背压与核心 · 章节题

C15.01 Project Reactor 背压机制
发布者-订阅者 Pull 模型、request(n) 需求信号、Mono/Flux 操作符组合；Backpressure 防止下游被冲垮。是响应式"少资源扛大并发"的本质。
章节Reactor背压
C15.02 WebFlux vs MVC 选型
WebFlux 事件驱动、少量线程 + 背压 vs MVC 阻塞式、每请求一线程；选型看 IO 密集度、团队心智与生态。呼应 ch04 VT 对比。
章节WebFlux
C15.03 R2DBC 响应式数据访问
异步非阻塞数据库驱动、Reactive Streams 流式取数；与 JDBC 阻塞原语差异、事务与连接池模型。让"全链路响应式"不卡在数据层。
章节R2DBC
C15.04 响应式错误处理与重试
onErrorResume/retryBackoff/超时兜底、错误传播与流终止语义；构成响应式链的可靠性防线，避免异常沉默。
章节错误处理
C15.07 Mono/Flux 语义与创建操作符
官方：Flux=0..N，Mono=0..1。创建用 just/defer/from*/create/generate/using；懒捕获用 defer。附录 §1。
章节MonoFlux
C15.08 map/flatMap/concatMap/switchMap
官方变换表：map 同步1→1；flatMap 并发不保序；concatMap 串行保序；flatMapSequential 并发重排；switchMap 最新并取消旧内层。
章节操作符
C15.09 zip/merge/buffer/groupBy
组合：concat/merge/zip/combineLatest；拆分：buffer/window/groupBy。空回退 defaultIfEmpty vs switchIfEmpty。
章节组合
C15.10 过滤/错误/时间/背压操作符
filter/take/single；onError*/retryWhen；timeout/delay；onBackpressure*。与超时预算、幂等重试对齐。
章节背压
C15.11 调度·Context·cache·block 边界
subscribeOn vs publishOn；share/cache/publish；block 禁用于 non-blocking Scheduler。Context 替代 ThreadLocal。
章节Scheduler
C15.12 背压未传递的症状与开关

背压断了会在某段无界缓冲里堆内存或丢请求。要会认症状并找到可关的缓冲点。

排查：见章节卡「落地排查」层；回滚：失败模式：无界 buffer 当「解法」；drop 未告知业务；阻塞调用藏在 flatMap。回滚点：恢复旧缓冲策略并限流上游。…

② 并发范式比较 · 章节题

C15.05 Virtual Threads vs Reactive 并发模型选型
VT 让阻塞式代码承载海量并发、Reactive 以事件驱动+背压获得并发；VT 心智低、Reactive 背压强。高 IO 会话场景是当前选型重点，与 ch04 紧密联动。
章节VT vs Reactive

③ 全栈落地 · 章节题

C15.06 响应式全栈架构落地
从网关→WebFlux→R2DBC/Mongo→消息的端到端响应式、线程模型与运营成本；明确"何时值得投入响应式"的权衡结论。
