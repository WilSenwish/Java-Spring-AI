① 内存区域与对象模型 · 章节题

C01.01 运行时数据区划分与 OOM 场景
堆（存对象、OOM 主战场）→ 线程共享区；虚拟机栈（方法栈帧 + 局部变量表，递归过深 StackOverflow）、本地方法栈 → 线程私有；方法区 JDK8 后迁入元空间，存类元数据/常量池，受本地内存限制；程序计数器不 OOM。答 OOM 要按区域归因：堆慢、方法区/元空间类过多、栈深、直接内存不足。
章节运行时数据区OOM 归因架构
C01.02 对象创建过程与内存布局
流程：类加载检查 → 给对象分配内存（指针碰撞 / 空闲列表，TLAB 线程私有加速）→ 内存零值初始化 → 设置对象头（Mark Word + 类型指针 + 数组长度）→ 构造方法。布局：对象头 / 实例数据 / 对齐填充。理解布局是分析锁升级、synchronized、偏向锁的基础。
章节对象头 Mark WordTLAB高级
C01.03 类加载机制与双亲委派
加载→验证→准备→解析→初始化五阶段。双亲委派：类加载请求先交给父加载器，父失败才自加载，保证核心类一致与安全。打破场景：Tomcat（Web 隔离自加载）、SPI（线程上下文类加载器）、OSGi 热部署。作用范围：加载一个类需要"全限定名 + 类加载器实例"二元组。
章节双亲委派打破委派
C01.04 JMM happens-before 规则
Java 内存模型定义 volatile/synchronized/lock/final/线程启动与终止等 8 条 happens-before 规则，解决并发可见性、有序性，同时给编译器/CPU 重排留空间（不改变单线程语义即可重排）。volatile 保证可见与禁止重排，但不保证原子性。答可见性必谈"工作内存主内存 + 内存屏障"。
章节JMMhappens-before可见性
C01.05 OOM 与内存泄漏的区别与排查
泄漏＝对象无法回收但不再使用，最终诱发 OOM。排查：保留现场 `jmap -dump` / `jcmd` 堆转储，用 MAT/JProfiler 分析支配树与 Leak Suspects，找 GC Roots 强引用路径；关注静态集合、ThreadLocal（弱引用+强引用残留）、缓存无过期、连接未关闭。回答要落到"工具 → 出图 → 定位到具体类"三步。
章节OOMMAT 支配树GC Roots
C01.06 直接内存与 NIO
DirectBuffer（堆外）由 NIO 的 ByteBuffer.allocateDirect 分配，减少一次从 JVM 堆到 OS 的拷贝，利于高性能 IO/零拷贝，由 Cleaner 关联的 DirectByteBuffer 回收（显式 System.gc() 或 Cleaner）。风险：堆外内存不纳入 GC 压力，配置 -XX:MaxDirectMemorySize；排查用 NMT（Native Memory Tracking）。
章节堆外内存NMT专家
C01.07 引用类型与 GC 回收
强引用不回收；软引用（内存不足前回收，适合缓存）；弱引用（下次 GC 即回收，WeakHashMap/ThreadLocalMap）；虚引用（仅跟踪回收，配合 ReferenceQueue 做堆外回收通知）。引用类型是缓存与堆外内存管理的基石，结合 GC Roots 判断可达性。
章节引用类型ReferenceQueue
C01.08 JPMS 模块系统对类加载的影响
JDK9 模块系统将 JDK 拆成 java.base 等模块，类加载改为"平台类加载器 / 应用类加载器，绑定模块图与模块路径"，引入强封装（java.* 可显式 opens）。影响：反射跨模块需 --add-opens；破坏"类路径平铺可见"假设；对类加载器委派仍是双亲委派为主。
章节JPMS模块封装专家
C01.09 JIT C1/C2/GraalVM C2 调优
C1（客户端编译器，快启动低优化）与 C2（服务端，慢启动深度优化）分层编译，配合解释执行与热点探测（-XX:CompileThreshold）。Graal JIT 作为可选编译器。调优点：方法内联、逃逸分析、锁消除、循环展开；用 -XX:+PrintCompilation / -XX:TieredStopAtLevel 诊断。
章节分层编译JIT专家
C01.10 JDK 17/21 新特性与升级迁移
Records（不可变数据载体）、Sealed（受控继承）、Pattern Matching/switch（类型解构）、Virtual Threads（轻量线程）、SequencedCollections（首尾操作）。迁移要点：移除如 -XX:+UseConcMarkSweepGC 等旧参数、Java 9+ 模块/反射封装、依赖第三方字节码兼容。注意区分语言特性与 JVM 实现。
章节Java21迁移
C01.11 OS 内存管理：虚拟内存、页表与 TLB
虚拟内存经分页映射到物理内存，页表记录映射、缺页中断触发装载；TLB 缓存页表加速寻址，因此 JVM 堆大并不等于常驻内存。分段/分页差异、多级页表压缩空间。答"堆为何是页表视图"体现操作系统→JVM 的纵向打通。
章节虚拟内存页表 TLB专家

VT 由 JVM 调度、阻塞自动卸载、pinning 需排查；Pattern 深度模式匹配；ZGC 分代吞吐提升 10–20%；SequencedCollection 统一首尾操作。跨 01/02/04 三章交叉。

八股 E12.01 常用数据结构选型与复杂度
数组/链表/栈/队列/HashMap 底层与增删查复杂度抉择：随机访问选数组、频繁增删选链表、查重缓存选哈希；选定依据是读/写/内存三个维度。
八股数据结构
八股 E12.05 排序算法复杂度与稳定性
快排（不稳,O(nlogn) 平均）、归并（稳,递归数组）、堆排（不稳,原地）；Java Arrays.sort 基础类型用双轴快排、对象用 TimSort 稳定归并。答按 O(nlogn)+稳定性分档。
八股排序
八股 E12.06 链表/数组高频算法：反转、环形、合并
单链表反转（迭代/递归）、快慢指针判环入口、合并两个/多个有序序列（归并降维）。写对边界与走查三连是得分关键。
八股链表
八股 E12.07 二分、双指针、滑动窗口模板
二分闭区间模板防死循环；双指针（相向/快慢）解决有序与环形；滑动窗口定长/变长维护窗口合法。核心是"窗口状态 + 收缩条件"。
八股模板
八股 E12.08 图 / 树遍历、DP 与贪心边界
DFS/BFS 适用可达性与层次；DP 三要素（状态/转移/边界），贪心仅适合"局部最优=全局最优"（区间、调度）不能套壳硬解；区分最优子结构。
