① 回收本质与收集器演进 · 章节题 + 八股

C02.01 GC Roots 与三种 GC 算法的本质权衡
GC Roots（栈变量、静态字段、常量、JNI、活跃线程）出发的可达性决定回收与否。三算法=标记-清除（快但碎片）、标记-整理（无碎片但移动）、复制（无碎片高效但有内存占用，适合新生代）。权衡本质是"吞吐 vs 延迟 vs 内存 vs 碎片"，没有银弹。
章节GC Roots三算法
C02.02 CMS/G1/ZGC/Shenandoah 差异与选型
CMS 并发标记清除、老年代关注延迟但有碎片与并发失败；G1 Region 化+可预期停顿、默认当代；ZGC 染色指针+读屏障，亚 10ms 大堆；Shenandoah 并发整理（G1 派生）。选型口诀：吞吐优先 Parallel、延迟敏感中小堆 G1、超大堆 ZGC、特殊低延迟 Shenandoah。
章节收集器选型ZGC
C02.03 JVM 参数如何设置
先定停顿与堆目标再选收集器：-Xms/-Xmx 相等免扩容振荡；新生代比例、-XX:MaxGCPauseMillis 设置停顿目标；-XX:+UseZGC 等选收集器；避免堆设过大吞本地内存或过小频繁 FullGC。参数是"目标驱动的约束"，非背数值。
章节JVM 参数
C02.04 线上 CPU 100% 快速定位
`top -Hp` 找 CPU 最高线程 → `jstack 线程ID转十六进制` 看堆栈 → 对应代码定位死循环/GC 线程/锁自旋。GC 型 100% 转查 GC 日志与内存；业务型看是否热点计算、无限循环、空转轮询。用 Arthas `thread -n 3` 一键抓最热线程。
章节CPU100%jstack
C02.05 线上 FullGC 频繁排查
看 GC 日志确认 FullGC 频率与耗时 → 判断是晋升过大（结合 CPU/内存确认）还是元空间、大对象/并发修改、缓存无上限。手段：堆转储 MAT 找大对象与 GC Roots、检查弱引用集合/ThreadLocal、JStat 观察各区。原则用数据驱动治本而非加大堆掩盖。
章节FullGC堆转储
C02.06 各场景 GC 收集器推荐配置
高吞吐批处理：Parallel + 大新生代；在线低延迟：G1 + 合理 pause target；超大堆延迟敏感：ZGC/Shenandoah；压测对比吞吐与 P99 后定。给"场景→收集器→关键参数"的组合，体现工程判断。
章节推荐配置
C02.07 Arthas 核心命令与诊断
`dashboard` 总览线程/内存/GC；`thread` 线程栈与阻塞；`trace/top -n` 定位高频方法；`jad/decompile` 反编译、`watch` 观测方法出入参、`heapdump`、`ognl` 动态执行。线上零侵入、即插即得的排查利器，配合承载的文件动态加载。
章节Arthas
C02.08 JFR 与异步 profiling
JFR 低开销采样（GC/分配/锁/方法样本）无需 `-XX:+UnlockCommercialFeatures`，`jcmd JFR.start/stop/dump`；异步 profiler 生成火焰图定位 CPU 热点与分配热点。对比线程 dump 是"瞬时快照 vs 持续画像"。适合压测与长期驻留排查。
章节JFR火焰图
C02.09 JVM 线上调优全流程
确立目标（吞吐/延迟/稳定）→ 基线压测拿数据 → 分析瓶颈（GC/内存/锁/IO 分层归因）→ 针对调参/改码 → 复测验证 → 固化配置与监控告警。全程"测量→定位→优化→验证"循环，拒绝拍脑袋改 -Xmx。
章节调优流程
C02.10 逃逸分析与标量替换
方法内对象若未逃逸，JIT 可做栈上分配、锁消除、标量替换（对象拆成字段寄存器态）。受益于 C2，减少堆分配与 GC 压力。答点：逃逸分析是"编译器把不可见对象变本地"，也是衡量 JIT 深度优化的门面。
章节逃逸分析标量替换
C02.11 Generational ZGC 生产调优
分代 ZGC（JDK21）年轻代用标记-复制、老年代并发整理，吞吐较单代提升 10–20%、停顿仍亚 10ms。调优：`-XX:+ZGenerational`、关注 `ZGC Cycles` 与分配速率、避免把堆设到让年轻代长期满导致高晋升量。适合超大堆 + 低延迟 + 中高吞吐兼备。
章节Generational ZGC
C02.12 GC/JVM 指标监控闭环
Micrometer 暴露 `jvm.gc.*`/内存/线程指标 → Prometheus 抓取 → Grafana 展示 → 阈值告警驱动调优。建设"GC 耗时/FullGC 次数/堆水位"核心大盘，把调优从救火变常态化。这是可观测性落地到 JVM 层的范本。
章节可观测Prometheus
