主题卡详情

① 索引与事务引擎 · 章节题 + 八股

C07.01 InnoDB B+树为何比 B树更适合数据库
B+树非叶子不存数据、内部节点可容纳更多 key 降低树高；叶子形成有序链表支撑范围扫描与顺序 IO；页式存储命中率高。对比 B 树：范围查询、磁盘 IO 次数、聚簇与二级索引回表。
章节B+树索引
C07.02 MVCC 如何实现 RC 和 RR 两种隔离级别
undo log 版本链 + Read View：RR 快照在首次读时生成（一致性读），RC 每次读都重新生成。trx_id 可见性算法判断当前行对事务是否可见，配合间隙锁弥补 RR 幻读。
章节MVCC隔离级别
C07.03 行锁/间隙锁/临键锁如何工作
Record Lock 锁单行；Gap Lock 锁索引区间防插入；Next-Key Lock=记录+前置间隙，RR 默认，防幻读。答要点：锁是加在索引上、按辅助索引定位时的间隙范围、与隔离级别的配合。
章节锁间隙锁
C07.04 Redo/Undo/Binlog 如何协同保证 ACID
Redo 崩溃恢复（持久性，物理日志，WAL 先行）；Undo 回滚+MVCC（原子性，逻辑日志）；Binlog 主从/归档。两阶段提交（redo prepare + binlog）保证 redo/binlog 一致。答"三日志职责 + 提交顺序"。
章节日志ACID
C07.11 MySQL 死锁检测原理与排查实战
InnoDB 依赖等待图检测死锁，victim 回滚代价小的事务；partially rollback。排查：SHOW ENGINE INNODB STATUS、LATESTDETECTEDDEADLOCK、统一加锁顺序、减少锁范围、索引优化命中。是事务并发的高频坑。
章节死锁

② 优化与扩展 · 章节题 + 八股 + 场景

C07.05 慢 SQL 如何排查与优化
慢日志→执行计划→定位全表扫描/回表/排序压力→加覆盖索引/改写 SQL/分页优化。口诀：explain 看 type/key/rows/extra（Using filesort/using temporary 是信号）。与 S03.02 实战互通。
章节慢SQL
C07.06 索引设计原则与优化策略
最左前缀、覆盖索引、区分度、避免冗余索引、小基数用不上索引、联合索引列序设计、失效场景（函数/隐式转换/反向/OR/like 前置%）。在"建什么索引"问题上展示成本意识。
章节索引设计
C07.07 分库分表如何设计与落地
垂直（按域分表）→水平（按 sharding key 取模/范围）；路由、扩容、分布式事务与跨分片查询是代价。核心：选对分片键保证扩展与查询局部性，配平滑扩容与配套中间件（ShardingSphere 等）。
章节分库分表
C07.10 EXPLAIN 执行计划如何解读
关键列：type(all→index→range→ref→eq_ref→const)、key/possible_keys、rows 估算、Extra(filesort/temporary/using index)。答"由 type 与 rows 判断是否走索引 + 定位瓶颈点"。
章节EXPLAIN
C07.12 在线变更(DDL)方案选型与治理
原生 ONLINE DDL、pt-osc/gh-ost 影子表切换、copy 方式的代价评估；锁表窗口、主从延迟、回滚预案、灰度分批。是"大表变更不动摇线上"的工程范式。
章节DDL
C07.13 隐式类型转换索引失效与自增空洞
字符列 vs 数值比较触发隐式转换→索引失效；自增主键空洞源于回滚/删除，主从可能错位需调 auto_increment_increment。答"类型一致性 + 自增语义"两个易错点。
章节隐式转换

③ 高可用与 ORM · 章节题 + 八股 + 场景

C07.08 MySQL 主从复制原理与延迟优化
binlog→IO 线程拷贝 relay log→SQL 线程重放；异步/半同步/组复制；延迟源（大事务/慢 SQL/并行度）与治理（并行复制、单条拆分、链路监控）。与 S03.03 主从延迟实战互通。
章节主从复制
C07.09 MySQL 高可用方案选型
主从+keepalived、MMM、MHA（半同步+自动故障转移）、MGR（组复制，Paxos 风格）；结合 GTID 与读写分离。选型看 RPO/RTO、数据一致性要求与运维复杂度。
章节高可用
C07.14 MyBatis 缓存、插件与 #{} vs ${}
一级缓存（session 级，默认）、二级缓存（namespace 级）；Interceptor 拦截四大对象；#{} 预编译防注入、${} 拼接有注入风险。是"ORM 下层原理 + 安全红线"的结合题。
章节MyBatis防注入
C07.15 MyBatis-Plus vs JPA 选型
MyBatis-Plus 偏 SQL 可控、分页插件/乐观锁(@Version)实现简单、批量友好；JPA/Hibernate 偏对象化、复杂关联映射强、缓存/懒加载完善。按团队 SQL 掌控力与数据复杂度选型。
章节ORM选型
