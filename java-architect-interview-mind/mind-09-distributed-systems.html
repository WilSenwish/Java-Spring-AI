① 事务与一致性 · 章节题 + 原理 + 场景

C09.01 CAP 定理证明与 BASE 理论指导实践
C/A/P 三者网络分区下只能取其二；BASE=基本可用+软状态+最终一致。实践：CP 场景（强一致敏感）与 AP 场景（可用+最终一致）取舍，配合服务降级设计。
章节CAPBASE
C09.02 分布式事务 2PC/3PC/TCC/AT/SAGA 原理与选型
2PC 阻塞、3PC 缓解；TCC try-confirm-cancel 需业务幂等与空回滚治理；Seata AT 自动补偿；SAGA 长事务补偿、不用全局锁。选型看一致性强度、业务侵入与吞吐。
章节分布式事务
C09.03 分布式锁三种实现对比
Redis(Redisson 看门狗，快)、ZK(临时顺序节点，强一致)、数据库(唯一索引，简单但慢)。从一致性、可用性、性能与运维四维选型，警惕单点与时钟问题。
章节分布式锁
C09.07 一致性哈希解决分布式缓存数据分布
哈希环 + 虚拟节点均匀分布、节点增减仅影响环上相邻 key，缓解缓存大规模失效。关注数据倾斜与热点处理。
章节一致性哈希
C09.08 接口幂等设计如何实现
幂等键（token/订单号）+ 唯一索引/分布式锁 + 状态机防重复提交；从支付、下单、消息消费等场景讲"同一操作多次生效一次"。核心：唯一约束兜底 + 语义幂等。
章节幂等
C09.12 分布式缓存的一致性保障
缓存层跨节点的一致性、与库的一致（呼应 ch08）、多级缓存失效广播；用版本号/增量更新控制并发覆盖。强调"最终一致 + 时效可控"。
章节缓存一致性
C09.07 分布式 ID 生成方案选型（ID 聚合）
UUID/雪花(Snowflake)/数据库号段/Leaf；关注趋势性、全局唯一、单调、业务含义与时钟回拨。选型看吞吐、排序要求与 ID 长度。
章节分布式ID

② 消息与时钟 · 章节题 + 原理 + 场景

C09.04 Kafka 高吞吐/可靠投递/消息顺序
顺序写+零拷贝+批量压缩+分区并发实现高吞吐；ack + ISR 配 leader 选举保证可靠；单分区内有序、需全局序用单分区/key 分区。答"吞吐的三板斧 + 可靠性参数 + 顺序边界"。
章节Kafka
C09.05 消息积压 1000 万条如何紧急处理
先止血（暂停消费修复下游）→ 定位积压原因（消费慢/幂等少/连接）→ 扩容消费者/临时拉大并发/并行重整 → 数据补偿。核心是"快速消费 + 源头治理"，与 S04.03 互通。
章节消息积压
C09.09 消息队列可靠投递与顺序
生产者确认 + 消费者手动 ack + 重试/死信；顺序靠单分区+单消费者或业务排序。可靠与不重(幂等)是同行题，结合对账兜底。
章节可靠投递
C09.14 分布式全局时钟与顺序保证
distributed log、Lamport/HLC 逻辑时钟、时间戳排序 vs 因果序；用"事件序号 + 逻辑时钟"避免依赖墙钟，处理时钟回拨。是共识与顺序的基础。
章节时钟排序

③ 治理与容灾 · 章节题 + 原理 + 场景

C09.06 拜占庭将军问题与共识算法
拜占庭容忍叛徒(n≥3f+1)；CFT(Paxos/Raft) vs BFT(PBFT)；选共识看故障模型与性能。是理解 Raft 在存储/ID/注册中心落地的理论基础。
章节共识
C09.10 链路追踪与可观测性落地
TraceId/Span、采样、跨服务透传；三支柱(Metrics/Traces/Logs)关联；SkyWalking/OTel。与 C11.09/C15 可观测呼应，S08.07 追踪专项互通。
章节链路追踪
C09.13 分布式会话共享方案
Session 复制/Redis 集中存储/JWT 无状态；从一致性、性能、登出与失效多维度对比。无状态架构优先 JWT，遗留场景用 Redis Session。
章节会话共享
C09.15 分布式容灾与多活架构
同城主备/同城双活/两地三中心/异地多活；RPO/RTO 指标、流量切换、数据同步与冲突处理。S08.01 异地多活是其场景化的实战延展。
章节容灾多活
C09.16 分布式事务新演进与 2026 选型
面向 saga/AT 的事务网格、基于消息的解耦与最终一致、去中心化 ID/存储的共识选型；从"强一致 vs 吞吐"给出 2026 务实组合。
章节事务演进
