① 思维模式 — 脑子里怎么想

决定你看待系统的方式：先回到本质，再看整体、辨类别、建层次，剥离抽象，在约束下权衡，并为失败与变化预留空间。融合百度"架构思维五要素"（全局/分类/分层/抽象/变化）与《面试核心方法论总结》序章①②组。

第一性原理 / 本质思维
无论面对多复杂的问题，先剥离"通常做法/行业惯例/已知结论"，回到问题的最基本事实与不可再拆分的原理，从本质出发重新推理，而非盲目类比或套模板。这是大厂面试最看重的核心：考察"解决未知问题的能力"而非"处理已知需求"。做法：连续问"为什么"到底层物理/数学/业务约束，再逐层重建。
本质思考反直觉推理未知问题求解
抽象与系统思维
从业务中识别核心概念、实体、流程，而非直接堆代码；把系统视为相互作用的整体，追问改动如何波及上下游。抽象讲究"度"：过低被细节淹没，过高脱离现实。Java 落地：接口、抽象类、泛型、领域模型、DTO/VO/Entity 分层。
纵向剥离横向关联抽象度
全局思维
看架构先看整片森林，再看一棵树：先回答系统核心目标、服务对象、主要构成、相互影响与成功标准，再深入细节。局部优化不等于整体优秀——若与核心需求无关或破坏模块连贯，反而是负担。落地：先画一张只含目标/对象/核心模块/外部环境/关键关系的全景图，建立坐标系再细化。
局部服从整体全景图整体与局部平衡
分类思维
复杂不是要素多，而是不同性质的要素混在一起。分类思维按合理标准把信息分到正确位置，降低理解与管理成本。有效分类三条件：标准服务当前目标、同一层级标准统一、类别少重叠且无重大遗漏。对应"边界"心法的横向维度——先辨类别，再定边界。
标准服务于目标同级统一标准少重叠无遗漏
边界与分层思维
分类解决横向归组，分层解决纵向秩序：按职责/抽象度/逻辑顺序划层，每层只处理本层问题，上层管方向约束、下层管落实支撑，避免越级依赖。对应边界心法。Java 落地：Maven/Gradle 模块化、Spring 分层、六边形架构、ArchUnit 守护依赖方向。
纵向分层依赖方向越级依赖模块化
解耦与组合思维
优先通过组合、接口、事件、消息解耦，而非继承与直接调用。核心原则：高内聚、低耦合、依赖倒置。Java 落地：依赖注入、AOP、事件驱动、策略模式、SPI 机制。
组合优于继承依赖注入事件驱动
权衡与取舍思维
没有银弹，任何方案都有代价：性能 vs 可读性、一致性 vs 可用性、微服务 vs 单体。架构师的核心能力是在约束下做出可解释、可回退的决策。参考 ATAM 识别敏感点与权衡点。
Trade-off约束决策ATAM
演进与变化思维
不追求一次设计完美，而保证系统能持续重构与演进。核心：让变更成本低、影响可控、可测试、可回滚。识别稳定部分与易变部分，为变化预留空间，但不过度设计。
增量演进稳定/易变分离避免过度设计
失败与不确定性思维
分布式系统中网络、磁盘、时钟、第三方都可能失败。默认所有调用都可能超时、重复、乱序、丢失。设计时先问：如果这一步失败，系统会怎样？复杂度三大症状之一即"未知未知"。
默认失败故障前置未知未知
并发与异步思维
理解 JMM、happens-before、线程池、锁、CAS、CompletableFuture、虚拟线程。核心：共享可变状态是万恶之源，优先不可变与无状态。异步不是目的，解耦与吞吐才是。
不可变优先异步为吞吐虚拟线程
数据与状态思维
系统本质是数据的流转与状态的变更。区分事实数据、派生数据、会话状态、缓存、持久化状态。核心问题：这个数据属于谁？生命周期多长？一致性要求多高？
数据归属状态管理一致性
成本与效率思维
架构决策需考虑开发、运维、机器、人力、时间成本。不是技术越新越好，而是"合适的技术解决合适的问题"。可对照四大成本类别（直接/运营/团队/机会成本）做技术经济评估。
全成本视角合适即最优
安全与信任思维
不信任任何输入，包括内部服务之间的调用。默认最小权限、安全默认值、纵深防御。将安全贯穿所有主题：拆分增攻击面、冗余需加密、缓存需鉴权。
零信任最小权限纵深防御
复杂度控制思维
高级开发与初级最大的鸿沟。复杂度的三个症状：变更放大、认知负荷（Ousterhout）、未知未知。用分而治之、信息隐藏、正交性、深模块与最小依赖关系控制复杂度，让每次变更最小化。
认知负荷变更放大分而治之
面向问题与业务思维
为用技术而硬造场景是反面教材。先定义要解决的业务问题与价值，再选择技术。以 ROI 与业务目标为导向，避免"技术傲慢"。对应《方法论》中"面向问题而非面向技术"。
业务价值ROI 导向不做氛围组
系统所有权 / 二阶效应思维
高级/架构师的边界不止于"写完自己的代码"，而是端到端拥有功能的长期行为与演化：了解代码如何融入更大的系统，并主动为未来变化负责。核心是二阶效应：每个技术决策都在创造约束或可能性，同时累积技术债或灵活性，需预判连锁影响而不做过早优化。
端到端所有权二阶效应技术债复利
判断力 / 技术前瞻思维
高级工程师区别于初中级的关键是判断力（judgment）而非堆码：在模糊与信息不全时做合理的取舍，并用清晰语言向各方解释风险。同时具备技术前瞻性——关注 AI 工程化、云原生、Serverless 等趋势，判断其适用边界而非盲目追新，让每个决策兼顾当下与未来。
判断力模糊决策风险表达技术前瞻

② 方法论 — 怎么做事

把思维落到可执行的流程与做法：先建模、再分层，用工程实践保障质量与稳定，并拥抱 AI 原生的新范式。对应《面试核心方法论总结》序章③组。

领域驱动设计 DDD
战略设计：限界上下文、上下文映射、子域划分；战术设计：实体、值对象、聚合、领域服务、仓储、领域事件。适用于复杂业务系统，帮助统一语言、划分服务边界。
战略设计战术设计统一语言
整洁架构 / 六边形 / 洋葱
核心思想：业务核心不依赖框架、数据库、Web 等外部细节。依赖规则：外层依赖内层，内层通过接口定义端口，适配器实现端口。C4 模型与 4+1 视图用于表达架构。
依赖倒置端口适配器C4 / 4+1
设计模式与持续重构
23 种经典设计模式是词汇表不是教条。重构是日常行为而非专项。核心：识别坏味道、小步重构、用测试保护。参考 Refactoring 目录与代码坏味道清单。
词汇表小步重构坏味道
TDD / BDD 测试驱动
TDD：红-绿-重构，先写测试再写实现，保证可测试性与设计。BDD：用业务语言描述行为，拉通业务、开发、测试。Java 落地：JUnit 5、Mockito、AssertJ、Cucumber、Testcontainers。
红-绿-重构测试金字塔
CI/CD 与 DevOps
代码提交即构建、测试、静态检查、打包、部署。核心：自动化一切、快速反馈、小步提交、主干开发。Java 落地：Jenkins、GitLab CI、GitHub Actions、Docker、Kubernetes。
自动化主干开发
可观测性工程
三大支柱：日志、指标、链路追踪。不是出问题才看日志，而是系统设计时就埋点。Java 落地：SLF4J/Logback、Micrometer、Prometheus、Grafana、OpenTelemetry、SkyWalking。
日志指标链路追踪
性能工程方法论
不要过早优化，但要有性能预算与基准。步骤：测量 → 定位 → 优化 → 验证。Java 落地：JMH 基准测试、JFR/JMC、Async Profiler、GC 日志分析、Arthas。
先测量再优化性能预算
容量与稳定性（SRE）
核心：SLO/SLI、错误预算、容量规划、限流、熔断、降级、隔离、弹性伸缩。把稳定性当工程问题而非救火。Java 落地：Resilience4j、Sentinel、Hystrix、线程池/信号量隔离。
SLO/错误预算限流熔断隔离
安全开发生命周期
安全左移：需求阶段威胁建模、开发阶段安全编码、测试阶段 SAST/DAST。依赖管理：定期扫描 CVE。Java 落地：OWASP Top 10、Spring Security、OWASP ZAP、Dependency-Check。
安全左移威胁建模
敏捷 / 精益 / 看板
核心：快速交付价值、持续改进、消除浪费、限制 WIP。架构要支持迭代交付，而非大而全的前期设计。演进式架构与 TDD、重构结合支撑持续交付。
快速交付限制 WIP
分布式一致性方法论
CAP/BASE/PACELC 决定取舍；Saga/TCC 处理长事务补偿；幂等性支撑重试。对应《方法论》高可用篇的分布式一致性、消息可靠性方法论。
CAPSaga/TCC幂等
架构决策记录（ADR）
把架构决策显式化、可回溯：背景、决策、取舍、结果四要素。避免被遗忘的决策与拍脑袋式选择，是"约束下可解释决策"的工程化载体。
背景决策取舍结果
AI-Native 应用架构
生成式 AI 已从单模型调用演进为多层协同的工程化系统，围绕可组合性、可观测性、可治理性三大支柱重构。核心范式：模型即构件（Model-as-Component）、提示即接口（Prompt-as-Interface）、反馈即编译（Feedback-as-Compile）。现代架构以数据流、任务编排与反馈闭环为驱动，而非以模型为中心。
可组合可观测可治理模型即构件
Agentic / LLM 工作流编排
单一的 Chatbot 已无法满足复杂业务，取而代之的是 Multiple-Agent 协同的智能体验（Agentic Workflow）。落地依赖成熟 Agent 框架构建具备规划、反思、工具调用（Tool Use）能力的系统，并把确定性工程体系与业务流深度融合。Java 生态关注 LangChain4j、Spring AI、语义缓存与可治理的编排层。
多智能体规划反思工具调用Spring AI

③ 原则 — 守哪条底线

把思维与方法论固化为不可逾越的纪律，避免回到技术债与混乱；也把架构师的贡献锚定在可衡量的价值与影响上。对应《面试核心方法论总结》序章④⑤组。

SOLID 设计原则
S 单一职责、O 开闭原则、L 里氏替换、I 接口隔离、D 依赖倒置。面向对象的基石；在现代分布式系统中可向 CUPID 属性（可组合/可预测/惯用/领域）与时俱进。
单一职责开闭依赖倒置
DRY / KISS / YAGNI
DRY 不要重复自己；KISS 保持简单；YAGNI 你不会需要它、不要提前实现。简洁三原则是控制复杂度与认知负荷的第一道防线。
不重复保持简单不过早实现
组合优于继承 / 迪米特法则
优先组合/委托而非继承，避免继承破坏封装；迪米特法则（最少知识原则）减少耦合。关注点分离让业务、技术、基础设施分开。
组合最少知识
依赖方向 / 无环依赖
稳定依赖原则：依赖指向更稳定的模块；无环依赖原则：包/模块之间不能形成循环依赖。用 ArchUnit 在构建期守护依赖方向，防止架构腐化。
依赖方向无环ArchUnit
关注点分离
业务、技术、基础设施分开，让每个关注点能独立演化与测试。这是"边界与分层思维"在工程上的强制落地。
业务/技术/基础设施
显式优于隐式 / 约定优于配置
关键逻辑不要藏在魔法与反射里（显式优于隐式）；框架默认配置合理以减少样板代码（约定优于配置）。二者平衡：默认约定，关键处显式。
显式约定
可测试 / 可观测 / 可回滚
可测试：任何模块能方便地单元测试；可观测：任何请求可追踪、任何状态可查询；可回滚：上线必须安全、可灰度、可回滚。三者是工程可靠性的三根柱子。
可测试可观测可回滚
无状态优先 / 不可变优先
服务尽量无状态、状态外置到 Redis/DB，才可水平扩展；不可变对象更安全，尤其并发场景。是"并发与异步思维"落到编码的强制要求。
无状态不可变
面向失败 / 优雅降级 / 幂等
超时、重试、限流、熔断、降级、隔离六板斧；优雅降级保核心链路；所有写操作尽量幂等以支持重试。是"失败与不确定性思维"的工程保障。
超时重试优雅降级幂等
安全默认 / 最小权限 / 纵深防御
安全默认值、最小权限、纵深防御是"安全与信任思维"的三条强制底线，贯穿所有主题：拆分增攻击面、冗余需加密、缓存需鉴权、排障需审计日志。
安全默认最小权限
度量驱动 / 小步提交 / 自动化
用数据说话，优化前先测量；每次提交小而完整，方便回滚与审查；构建、测试、部署、监控、告警全自动化。是"成本与效率思维"与工程实践的结合。
度量驱动小步提交
CUPID 属性（现代补充）
Dan North 提出的现代设计属性：Composable 可组合、Unix 理念（做好一件事）、Predictable 可预测、Idiomatic 惯用、Domain-based 基于领域。作为 SOLID 的演进视角，聚焦可观测与可演化性。

以价值 / 影响衡量成果
架构师的价值不由代码量或技术选型的"先进程度"衡量，而由对业务、工程质量与长期可演化性的真实影响衡量。对应 2026 大厂的晋升审视：关注你如何理解端到端影响、如何在关键节点用判断力做出别人做不到的取舍，并用可度量的成果（性能、可用性、交付效率、成本）证明贡献。
