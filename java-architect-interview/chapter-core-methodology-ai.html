AI 应用开发方法论

41 张 AI 应用开发方法论卡片，按「道—法—术」组织，是 核心方法论 M 篇 的 AI 专项延展。非确定系统的生产落地需要独立的方法论分层：道定概率心智与评测优先，法立生命周期框架与治理闸门，术落具体反模式与实现。

道 6 卡 | 法 15 卡 | 术 20 卡 | 合计 41

AI 系统的输出是非确定的；把它当确定性系统验收，会在生产以静默方式失败。本专篇把「概率心智、评测优先、语义可观测、人仍在环、协议收敛、知识时态」六条第一性与「生命周期框架、治理闸门、发布门禁」等法的骨架收敛为可引用的道/法/术条目。横切面（可靠/安全/可观测/成本/变更/组织）回指 M 篇对应 M 组。

读法：读任一 L 卡都要能挂回 M 篇的「道—法—术—器—势—纪」因果链——道定取舍边界，法落成骨架与责任表，术打招式并暴露调参，器固化门禁，势判断时机，纪沉淀研发前段流程与软技能。L 卡的 Java 实现细节进 C12，工程化清单进 G07，AI 工程纵深进 A 轴。

L01AI 应用开发方法论 · 道（第一性与心智模型） 道 · 专篇延展 · 6

AI 系统是非确定系统；心智模型决定后续所有招式的方向。下列卡片把 A 轴论证与 MD 合成段收敛为第一性判断。

L01.01
不确定性是第一设计对象（概率系统心智）
核心洞察
AI 系统的输出是非确定的；把它当确定性系统验收，会在生产以静默方式失败。设计的第一动作是把「概率」当成一等公民，而不是事后补丁——先定义哪些输出错了却不抛异常，再写功能。
原理映射
三条第一性事实（推理概率性、检索噪声、工具副作用）共同决定 AI 制品不能套用「异常即失败」的传统心智；A01.01 的 Model+Harness 二分、A02 上下文工程、MD 笔记 1.2「不确定性是设计对象」指向同一结论。回指 L03.02 确定性边界、L03.05 静默失效立法。
工程表达
立项书先列「哪些错不抛异常」再列功能清单；判定句：凡把概率组件当确定性组件验收的方案，默认不可上线，须先有语义层监控与回归基线。
L01.02
以评测为中心（eval-first）
核心洞察
没有评测的资产（Prompt / 索引 / 模型 / 工具）等于没有回归基线；评测先于功能，而不是功能做完再补测试。评测集是 AI 制品的「编译单元」。
原理映射
A06 评测 vs 监控四类的设计、A06.02 Golden Set + CI 门禁、A17.01 把 Golden Set 定为效果回归真值锚点，与 L03.01 变更必回归同源。评测集污染（A06.04 Goodhart、judge 同源偏见）是 eval-first 的反面教材；C12.36 指出类型系统通过不等于业务语义正确。
工程表达
任何新能力先建最小 Golden Set（≥50 题）再开发；判定句：无独立评测环不上线，评测集与生产流量严格隔离，禁止把生产样本回灌为基线。
L01.03
语义可观测优先于语法可观测
核心洞察
HTTP 200、低延迟、零错误率不构成 AI 系统安全的证明；语义正确率与行为基线偏离才是判据。语法层全绿恰恰是风险信号而非安全证明。
原理映射
A19.03 把监控对象从「调用成功」转为「行为偏离基线」；L03.05 立法、L03.09 准入前置；C12.40 把语义指标做成一等埋点。传统可观测（M06.07 信号立法）是语法层，AI 要求再叠一层语义层。
工程表达
看板必须含语义正确率与行为基线两项；判定句：全绿但无转化、无人工确认时，应能触发盲集抽样复核与 kill switch，而不是宣布健康。
L01.04
人仍在环：human-in-loop 作为仲裁与兜底
核心洞察
对资金、权限、不可逆动作的 AI 决策，人必须是最终仲裁；自动化率不是越高越好，而是在可解释边界内最大化，而非为减员而减员。
原理映射
A07 四大风险面与分层防护、MD 笔记十 人机协同；L03.01 工具契约把 HITL 列为可写工具必填项。人环直接压低 fail-plausible 与组合越权两类静默风险。
工程表达
可写 / 高后果工具默认挂 HITL；判定句：能说出哪些动作必须人工确认、确认界面给什么上下文（检索依据、影响范围、回滚方式），才叫人环到位。
L01.05
平台 / 协议收敛降低协作税
核心洞察
多 Agent / 多工具 / 多模型若各自定义接口，协作税随参与方平方上升；收敛到少量协议（MCP / A2A）与统一平台，把 N×M 降到 N+M，是规模化落地的结构性前提。
原理映射
A04.02 MCP 本质 N×M→N+M、A10.02/A10.03 协议三角色与 A2A Task 状态机；MD 笔记 6.2「中间形态陷阱」、6.3「79% 的规格层」、6.4 协议税。回指 M07 分布式心智（接口收敛）与 M05 演进。
工程表达
新工具优先接入既有协议而非自造 SDK；判定句：能说出协作税来自哪层接口不一致、收敛后省下多少适配，才叫平台化到位。
L01.06
知识会静默失效：语义时态是第一公民
核心洞察
检索 / 记忆 / 索引背后的知识会随业务演进过期，且过期不报错；语义时态（这段知识现在还成立吗）必须作为一等概念管理，而非用最后修改时间糊弄。
原理映射
A02.04 记忆写入准入闸门与谱系、MD 笔记 4.3 知识失效（语义静默失效）、4.4 记忆腐化与遗忘权；L03.03 验证不可自证在知识维度的延伸。回指 M11 变更闸门与 M05.05 技术债。
工程表达
知识入库带生效窗口与失效信号、来源可追溯；判定句：能指出哪些知识有时态、过期如何被发现与回滚，才叫语义时态受控。

本专篇 不重写通用方法论，仅把 AI 工程化的特殊风险（静默退化、语义时态、人在环）落到专属卡，横向回指既有 M 组。

L02.01
全生命周期阶段框架（立项 → 退役 五段）
核心洞察
AI 应用应沿「立项·选型 → 数据·上下文 → 编排·工具 → 评测·发布 → 运维·治理·退役」五段组织；每段失败模式与门禁不同，不能用一套验收覆盖全周期。把生命周期显式切开，才能定位每类问题该在哪道闸门前被拦下。
原理映射
MD deep-dive 的 18 工程维度与 §1.5 交叉索引即按此分段组织；A01.01 的 Model+Harness 二分指出建模与装配是两个阶段。回指 M05 工程决策与 M11 变更纪律（退役属变更纪律末端），并与 L03.01 变更必回归衔接于「发布段门禁」。
工程表达
判定句：每段必须写明「本段退出标准与下一阶段入口门禁」，缺一段即视为架构缺环。检查项：五段是否各配评测集、回滚点与退役清单；立项书是否先列不确定性与静默失效清单再列功能。
L02.02
能力准入闸门：登记 → 放行（capability admission）
核心洞察
任何新能力（工具 / 模型 / 检索源）先登记元数据与风险等级，过准入闸门才放行到编排层，禁止边写边直接暴露给 Agent。准入闸门是控制面的一道前置硬约束，把「能不能用」和「怎么用」分开裁决。
原理映射
A13.03 能力准入闸门给出登记→放行流程；A13.04 的组合版本与退役窗口规定能力生命周期。回指 L03.06 状态写入准入与 L03.02 确定性边界（能力须落在控制面而非 LLM 侧），对应 M11 变更纪律的登记口径。
工程表达
判定句：未登记能力不得接入运行时；准入闸门必含鉴权、幂等、HITL、回滚四项必填。检查项：能力注册表是否含风险等级、owner、版本哈希与退出策略。
L02.03
三层测试与发布门禁（unit / eval / chaos + 非劣效界值）
核心洞察
AI 制品需要三层门禁：确定性单测（工具 / 网关 / 解析）、语义评测（黄金集指标断言）、混沌注入（故障与对抗）。放行以「非劣效界值」而非「不低于旧分数」为判据——分数持平但行为漂移同样不可发布。
原理映射
A06.03 三层测试与发布门禁；A06.02 Golden Set + CI 门禁定义评测环；混沌由 A17.03 故障注入承担。回指 L03.01 黄金集回归与 L03.07 评测独立性（评测集与生产流量隔离）。
工程表达
判定句：任一维度退化超非劣效界值即阻断，灰度按 1% → 10% → 50% → 100%。检查项：三层是否各有独立阈值与盲集；fail-plausible 是否归入回归失败而非待观察。
L02.04
反模式速查
核心洞察
AI 工程有稳定的反模式集合：缓存 key 只按 query、隔离写在 LLM 侧、摘要压缩丢否定约束、快照不可复现、组合越权每步合法端到端违规。它们应作为上线前 checklist 而非事后复盘素材。
原理映射
MD deep-dive 反模式附录与 notes 十六「反模式与优先级」逐条列出；A20.01 注入防护四道闸、A27.05 路径级权限对应组合越权类反模式。回指 L03.02 确定性边界与 L03.05 静默失效立法。
工程表达
判定句：反模式清单逐项打勾通过才进入发布评审。检查项：是否覆盖隔离失效、缓存错配、快照不可复现、权限 laundering 四类；每条反模式是否配残余声明。
L02.05
全景架构剖面
核心洞察
一个 AI 应用应能在「前置护栏 → 检索 → 记忆 → Prompt 组装 → 网关 → 决策 → 工具 → 后置护栏 → 记忆写入」剖面上，定位每一能力的控制面 / 数据面归属。剖面不清，责任与重试就无处安放。
原理映射
MD notes 十七「全景架构剖面」给出完整链路；A27.01 控制面推导、A04.02 工具网关定义控制面唯一可信边界。回指 L03.02 控制面纪律与 M07 分布式心智（接口收敛）。
工程表达
判定句：任一能力必须能指出它落在控制面还是数据面、由谁负责重试。检查项：剖面图是否标注网关、护栏与记忆边界；LLM 是否仅作网关调用客户端而非直连下游。
L02.06
供应链与模型侧工程（退役窗口、组合版本、ModelSBOM）
核心洞察
模型与依赖是供应链资产，供应方静默升级等价于一次未走门禁的生产变更；须锁定组合版本、约定退役窗口，并对每个上线模型产出 ModelSBOM。模型不是函数，是带契约的外部依赖。
原理映射
A13.04 组合版本与退役窗口；C12.41 ModelSBOM 与谱系；A23.04 配置谱系与灾备把 ModelSBOM 列为灾备对象。回指 L03.08 变更单元与回滚点、M11 变更纪律的退出机制。
工程表达
判定句：供应方静默升级须触发回滚预案；每次模型变更产出 ModelSBOM。检查项：是否记录基座 / 微调 / 偏好集 / 对齐版本哈希与退出策略；组合版本是否一并钉死。
L02.07
多租户隔离与资产退役
核心洞察
多租户 AI 必须把向量分片、记忆、会话数据、审计视图按租户隔离，且权限隔离落在控制面而非 LLM 侧；资产退役须有销毁清单（权重擦除、备份同步删除、第三方侧确认）。粗放到只做入口鉴权就会跨租户串扰。
原理映射
A09.06 隔离（模态 / 租户隔离）；MD notes 十五「多租户与资产退役」给出侧信道与销毁规范。回指 L03.02 确定性边界（隔离绝不能写在 LLM 侧）与 M09 高可用隔离原则。
工程表达
判定句：跨租户检索 / 记忆串扰零容忍；退役须含权重擦除与备份同步删除清单。检查项：租户侧审计视图与遗忘权接口是否独立；多租户 Agent 是否共用同一工具池。
L02.08
组织与变更治理
核心洞察
AI 失败常源于组织与责任边界不清，而非模型本身；变更须走分级评审，监督容量应作为设计约束而非事后补丁。职责边界不清的能力不予立项，比换模型更有效。
原理映射
MD notes 十六「组织、人机协同与高阶治理」与来源 A 的模块责任边界；A26.03 组织层失效与影子 AI 指出技能梯子断裂与监督空心化。回指 M05 工程决策、M11 变更分级矩阵、L03.04 长链路步数预算。
工程表达
判定句：职责边界不清的能力不予立项；L3 变更（护栏 / Agent 闭环）须变更委员会 + 窗口期 + 冻结。检查项：是否定义监督容量上限与升级路径；影子 AI 是否在治理视野内。
L02.09
成本 / 容量三维（CPS + 三层成本）
核心洞察
以「每完成任务成本（CPS = 单次尝试成本 ÷ 成功率）」为第一指标，而非 Token 单价；成本分推理 / 基础设施 / 运营三层，第三层（人工监督税、协议税、精炼循环）是最大隐藏项。Token 便宜 20% 但失败率更高，CPS 反而更贵。
原理映射
A22.03 CPS 单位经济学与二阶成本（监督税 / 协议税 / 精炼循环 / 能耗碳排）；MD notes 六「成本与单位经济学」给出三层成本结构。回指 L03.01 成本阈值与 M06 运行时容量。
工程表达
判定句：只报 Token 单价不算成本，须给 CPS 与三层分摊。检查项：是否计入监督税、协议税、精炼循环与审查-精炼占比；预算硬顶是否触发降级。
L02.10
合规按功能叠加
核心洞察
合规不是单点开关，而是按功能（检索 / 生成 / 工具调用 / 跨域传输）叠加的独立护栏；输出合规由独立服务裁决，不信任模型自述。每一功能层声明自己的合规边界，才能避免「整体合规、局部越权」。
原理映射
MD notes 3.3 编排分级与硬上限、来源 A 六·合规将合规审核列为独立后置服务；A20.01 注入防护四道闸按成本递增排列。回指 M13 安全纵深防御与 L03.02 控制面纪律。
工程表达
判定句：每项功能须声明其合规护栏与责任边界；合规审核独立于 LLM。检查项：是否覆盖数据跨境、遗忘权、生成合规三类；审计链路是否可证明「谁、何时、输入、输出」。
L02.11
多 Agent 协作税与协调衰减（103 天遥测）
核心洞察
多 Agent 把失败推到协调层：MAST 对 7 框架 1600+ 轨迹标注显示 79% 失败在规格与协调层（步骤重复 15.7%、推理-行动错配 13.2%、未感知终止 12.4%）；103 天遥测中共识提案从 121→13→6、138 次审批仅 18 次明确决定，协调被旁路而非坏掉。
原理映射
MD notes 6.1 / 6.5 协作税与协调衰减；A04.02 协议收敛（N×M→N+M）、A10.02 / A10.03 协议角色与状态机降低协作税。回指 L01.05 协议收敛与 M07 分布式心智（接口边界）。
工程表达
判定句：可协调性须在写第一行 prompt 前建模，不能委托给协调发生时。检查项：是否定义终止条件、角色边界、状态同步与升级路径；是否设置信任边界防 social proof 污染。
L02.12
记忆生命周期治理（腐化 / 遗忘权 / 继任可移植）
核心洞察
记忆会静默腐化：健康度报告显示 >180 天 58% 记忆过时、34% 错误记忆置信度更高、93% 缺生命周期管理；遗忘权须可验证删除（向量库探测语义近邻），继任继承的是经审计的能力而非 episode trace。
原理映射
MD notes 4.2–4.6 知识失效 / 记忆腐化 / 继任与可移植；A02.04 记忆写入准入闸门与谱系给出写入治理。回指 L01.06 语义时态、L03.06 状态写入准入与 M11 数据治理（保留期）。
工程表达
判定句：记忆写入走生产变更准入，删除须可验证且继承最严格保留期。检查项：是否记录来源谱系、遗忘权接口与继任移交清单；episode-specific trace 是否排除在活跃记忆外。
L02.13
数据生命周期治理（评测集版本/漂移·合成数据·数据飞轮）
核心洞察
AI 系统的数据有三类生命周期——训练/知识数据、评测数据、生产行为数据；评测集会随模型与业务静默漂移，必须像代码一样版本化与回归；合成数据/数据飞轮是规模化持续学习闭环的燃料，但飞轮本身要防污染与偏见放大。
原理映射
回指 L01.06 知识静默失效、L02.03 三层门禁、L03.07 评测独立性；A17 非确定性断言与 Golden Set；C12.29/33 评测集最小闭环；A21 知识库 ETL。数据飞轮与 L01.01 不确定性心智一致——用生产信号反哺评测与知识，但须隔离噪声。
工程表达
判定句：评测集无版本与漂移告警即视为不可信基线；合成数据须标注来源与去偏。检查项：评测集是否随每次模型/检索变更跑回归；漂移超阈值是否阻断发布；数据飞轮写入是否经清洗与偏见抽检。
L02.14
受监管行业 AI 合规检查清单（合规按功能叠加）
核心洞察
合规不是上线后补，而是按功能叠加的设计约束；金融/医疗/政务等场景需可解释、可审计、可撤回、数据本地化；监管报送与模型备案要在设计期预留埋点。
原理映射
回指 L02.10 合规按功能叠加、M13 安全设计、L01.04 人仍在环（高风险决策留人工仲裁）、A07 合规落地、C12.15/19 安全纵深；遗忘权与 L02.12 记忆生命周期治理、L03.18 记忆写入闸门衔接。
工程表达
判定句：受监管功能缺可解释/审计/撤回任一项即视为未合规。检查项：决策是否可解释并留痕；是否支持被遗忘权与数据导出；模型/数据来源是否可备案；敏感字段是否本地化与脱敏。
L02.15
算力/FinOps 工程抓手（GPU 利用率·调度·二阶成本）
核心洞察
推理成本大头在算力而非仅 Token；GPU 利用率、碎片化、调度策略决定单位经济；FinOps 要算二阶成本（缓存命中降低重算、降级避免雪崩、批处理摊薄固定成本）。
原理映射
回指 L02.09 成本/容量三维、L03.10 缓存体系、L03.11 LLM 网关路由、A22 CPS 单位经济学、C12.26 Token 成本治理；算力调度与 M09 容量评估、M06 隔离原则同构。
工程表达
判定句：成本优化只看 Token 单价而忽略 GPU 利用率即视为片面。检查项：批处理与流式是否摊薄固定成本；闲置与碎片化是否监控；降级/缓存是否计入二阶成本收益。

L03.01
AI 变更必回归与工具有契约
核心洞察
模型、Prompt、索引、工具中的任何改动都必须过同一黄金集；可写工具默认要求鉴权、幂等、超时与人工确认（HITL）。 量化门禁：黄金集 ≥ 50 题；要点覆盖 ≥ 基线 −2%；安全拒答率 = 100%；P99 延迟 ≤ 基线 × 1.1；单次调用成本 ≤ 基线 × 1.1。四项同向才放量，灰度按 1% → 10% → 50% → 100%，每档观察 ≥ 30 分钟。 工具契约必填项：鉴权主体、幂等键、超时、最大重试、是否可写、是否需要 HITL、配额上限。 四方版本化（Prompt / 索引 / 模型 / 工具）必须各带可一键执行的回滚点，变更单写明回滚目标版本与执行人；评测集与线上流量严格隔离，禁止把生产样本直接回灌为基线，避免评估污染。
原理映射
章节 12 与 AI 场景：版本化、成本与质量并列、应急可演练。AI 制品的不确定性来自模型与检索，因此「可评测」是它区别于普通代码的唯一额外要求。 四方版本化（Prompt / 索引 / 模型 / 工具）的意义在于可回滚：任一维度变更都必须能一键切回上一版，并在变更单中写明回滚点。 fail-plausible（错误被转化为流畅叙述且返回成功）须归入回归失败而非待观察，因为它绕过了以异常为依据的传统门禁；这正是「可评测」作为 AI 制品额外要求的原因。 版本与回滚按 A23.01 的「版本—变更—回归」三位一体管理，没有回归记录的版本不允许发布；A23.04 把配置谱系与 ModelSBOM 列为灾备对象，供应方静默升级等价于未走门禁的生产变更；C12.34 把工具副作用等同配置发布，须灰度、卡点、可关停。
工程表达
无测试集不上线；放量靠「离线评测 + 小流量双确认」，而不是靠线上观感。 回答时给出黄金集规模、四项阈值与回滚点；若被追问效果，先给依据命中（检索文档 ID）与拒答率，再给流畅度等主观指标。 回答时先说清四方回滚点与评测集隔离方式，再给阈值；若被追问监控全绿是否安全，应能指出语义正确率与行为基线偏离才是判据。 判定句：任何制品变更（Prompt / 索引 / 模型 / 工具）必须先有回归记录与可演练的回滚点，才允许进入灰度。
L03.02
确定性边界纪律
核心洞察
校验、权限、参数、限流、幂等、熔断、审计一律置于模型之外；模型只产出候选与解释，不裁定业务正确性。凡是判定错了会造成资金、权限或状态损失的动作，必须由确定性控制面执行或否决。
原理映射
推理概率性意味着同一 Prompt 在不同上下文可给出不同结论，概率组件不担保业务正确性。把确定性校验留在 LLM 之外，等于把失败域从不可判定压缩为可测试；L03.01 的黄金集回归门禁是这条纪律的推论而非替代品——门禁发现退化，硬拦截阻止退化造成损失。对应 A27.01 的控制面推导与 A27.05 的路径级权限。 A27.05 进一步指出安全是路径属性而非各节点属性的并集，组合越权靠逐点鉴权原理上拦不住；A20.01 的注入防护四道闸按成本递增、信任递减排列，前道拦得越早后道越省。
工程表达
回答时先划出「LLM 之外」的控制面清单：参数类型与范围校验、身份注入与鉴权、幂等键、限流与超时、熔断降级、审计留痕，再说明模型只产候选。判定句：把「请谨慎」写进 Prompt 而没在网关做硬拦截，即违反本纪律。 判定句：组合越权的唯一判据是沿工具链的权限预算是否只收紧不放宽，而非每个工具各自鉴权通过。
L03.03
验证不可自证
核心洞察
验证器必须独立于被验证组件，证据必须是硬证据：Schema 校验、文件存在性、API 返回码、校验和、业务规则断言。让第二个 LLM 给第一个 LLM 的作业打分，只是把同一个概率性再乘一次，不产生可判定证据。
原理映射
三条第一性事实之①是推理概率性：被验证组件的输出不能作为自身正确性的依据。A27.03 论证了验证环为何必须闭合到硬证据；L03.01 的评测集隔离（禁止生产样本回灌基线）正是「不自证」在评测维度的落实。若验证器与生成器共享 Prompt、模型版本或检索库，相关性会把同一个盲点复制成共识。 A06.04 补上评测维度：评测集吸收生产流量即被自身输出污染，judge 与被测模型同源会把共同偏见放大成「一致通过」；C12.36 指出结构化输出转换器只兑现 Java 类型不兑现业务语义，类型系统通过不等于业务正确。
工程表达
无独立验证环不上线；能说出验证器归属、证据类型与拒绝策略。判定句：Schema 强校验不过即拒绝并降级，不把模型原始文本交给业务代码裸解析；被追问可靠性时先给硬证据清单，再给主观评分。 判定句：反序列化成功只说明字段可赋值，金额单位、枚举取值、外键与状态机迁移仍须在业务规则层逐个校验，任一失败即短路。
L03.04
长链路步数预算
核心洞察
端到端可靠性是各步成功率的乘积，退化由步数驱动，而非由上下文窗口长度驱动。换更长窗口的模型或压缩上下文，都不改变乘积结构；唯一有效的是收缩复合指数。
原理映射
复合相乘是 A27.02 的数学事实：单步再高，步数一多也会把整体拉低。确定性步骤移出 LLM、窄接口拆短链、每步交接强制校验，本质都是减少参与相乘的概率环节。上下文压缩只改变信息量，不改变环节数，属于把预算花在错误的维度上。 A02.02 论证上下文压缩是预算动作而非可靠性动作：它改变信息量不改变环节数，既不减少步数也不增加硬约束，与 A27.02 的乘积结构同源。
工程表达
设计时先定最大步数与每步交接校验点，再谈编排框架；超限即拆为可独立验收的子任务或转人工。判定句：能画出链路并指出哪几步是概率环节、哪几步有硬证据校验，而不是回答「加大上下文窗口」。 判定句：退化由步数主导，扩窗口或压缩上下文都不改变乘积结构，唯一有效的是收缩复合指数。
L03.05
静默失效立法
核心洞察
返回 200 OK 但语义错，列为一级故障，不按「成功」计入可用性。静默失效有四型：成功码下的语义错、行为随时间漂移、错误被转化为流畅叙述、用户静默放弃；传统监控全绿恰恰是风险信号而不是安全证明。
原理映射
A28.01 把 fail-plausible 单列，是因为异常驱动的传统门禁对这四型全部失效。M06.07 的信号立法要求先定义什么算故障，本卡在 AI 场景补上「语义正确率」这一信号；K07 静默塌方给出反例，C12.40 给出语义指标埋点的实现路径。把语义错当成功，会让 SLO 与告警同时失真。 A19.03 把监控对象从「调用是否成功」转为「行为是否偏离基线」；A28.01 把静默失效拆为四型（语义错、行为漂移、fail-plausible、静默放弃），失真位置各不同；C12.40 指出语义错不体现在 HTTP 状态码，必须自埋语义维指标。
工程表达
监控看板必须有语义正确率与行为基线偏离，不能只看成功率、延迟与错误率。判定句：能说出「全绿但无转化 / 无人工确认」应如何触发告警，并给出盲集抽样复核与 kill switch 的触发条件。 判定句：语义错不以异常形式出现，监控全绿恰恰是风险信号而非安全证明。
L03.06
状态写入准入
核心洞察
记忆、索引、工具状态等持久化写入按生产变更准入：每次写入都要能回答「未在他处制造退化」。局部看似合理的记忆更新，会沿后续调用链漂移到未授权的行为轨迹。
原理映射
状态累积偏差是 A27.04 的机制：单步偏差可逆，跨会话累积后不可逆。L03.01 管模型 / Prompt / 索引 / 工具这些制品的变更回归；本卡管运行时持久化状态的写入准入，两者互补不重叠。谱系与回滚点在这里不是可选项——没有谱系就无法定位是哪次写入把行为带偏。 A27.04 把累积性定为第一性事实：单步偏差可逆、跨会话累积不可逆，准入标准须从「本次写入是否正确」改为「是否在他处制造退化」；C12.42 据此把记忆按生产变更准入，写入前盲集比对、写入后按谱系回滚。
工程表达
变更单写明写入来源谱系、可一键回滚点、盲集比对结果与拒绝策略；无回滚点不写入。判定句：能区分「制品变更」与「状态写入」两类门禁，并说明影子流量隔离与稳态腐化熔断分别在哪一层生效。 判定句：记忆不是缓存而是长期生效的配置，准入判据是「别处没制造退化」而非「本次局部有效」。
L03.07
评测独立性
核心洞察
评测集与评估器必须独立于生成链路；生产样本回灌基线会让门禁与被测系统共同退化，形成自证循环。judge 与被测模型同源时，共同偏见被放大成「一致通过」。
原理映射
评估可信度优先于验证环、复合收缩与状态准入（A27.01 的依赖顺序推导）。A06.04 论证评测集污染与 judge 同源偏见；A17.01 把 Golden Set 定为效果回归的真值锚点；C12.29 / C12.33 给出冻结版本与隔离实现。与 L03.03 划界：L03.03 写「验证器不能自证」，本卡写「评测资产自身的独立性与污染」。
工程表达
基线冻结、样本来源隔离、评估器版本登记三项准入。判定句：能说出评测集版本与 judge 版本，并证明二者与被测系统无同源污染，才叫可信评测。
L03.08
变更单元与回滚点
核心洞察
模型、Prompt、索引、工具的任一组合变更必须登记为同一变更单元并自带回滚点；没有回滚点的变更不允许进入灰度。
原理映射
A23.01 把 Prompt 治理定为版本—变更—回归三位一体，A23.04 把配置谱系与 ModelSBOM 列为灾备对象；C12.30 / C12.34 给出灰度与影子流量实现；C12.41 用快照支撑重放与回写。与 L03.01 划界：L03.01 管「改动要过黄金集」，本卡管「什么算一个变更、回滚点从哪来」。
工程表达
变更单必填「包含哪些制品、回滚到哪个三元组、回滚验证项」。判定句：能列出本次变更的完整制品清单与对应回滚点，才放行灰度。
L03.09
语义可观测准入
核心洞察
在把「语义错」列为一级故障之前，必须先定义并埋点能判出语义错的信号；否则立法不可执行，全绿不构成安全证明。
原理映射
A19.03 把监控对象从「调用成功」转为「行为偏离基线」；C12.40 用 MeterRegistry 把语义正确率做成一等指标；C12.41 用快照支撑故障回放；K07 给出静默塌方反例。与 L03.05 划界：L03.05 立法，本卡管立法的前置条件。
工程表达
上线前检查表——语义正确率信号、行为基线、Bad Case 回写路径三项齐备才放行。判定句：能指出「全绿但语义错」如何被监控捕获并触发告警，才叫立法可执行。
L03.10
缓存体系
核心洞察
语义缓存能压低推理成本，但 key 必须包含 user_id、session_id、模型版本、采样参数与检索上下文，不能只按 query 哈希；否则上下文或权限不同却返回同一答案，造成信息错配与越权复用。
原理映射
MD 来源 A·模块6 缓存分层要求缓存 key 含租户与上下文；A08.04 上下文预算说明缓存须在预算内复用。回指 L03.01 成本阈值、M09 缓存策略与 L02.09 三层成本（缓存维护成本计入 CPS）。
工程表达
判定句：缓存 key 不含租户 / 上下文即视为越权复用，默认不命中。检查项：命中率与维护成本同看；过期与失效信号是否驱动重建；相似 query 不同权限是否隔离。
L03.11
LLM 网关与模型路由
核心洞察
所有模型调用须走统一网关收口（路由 / 版本绑定 / 计量 / 缓存 / 重试 / 熔断 / 日志 / 水印），并按场景置信度分级路由——高可靠场景误用廉价模型会令成本与质量双崩。网关即准入面，LLM 只是其调用客户端。
原理映射
MD 来源 A·模块6「LLM 网关、模型路由、多模型、负载、降级、故障转移」给出网关职责；A13.03 能力准入把网关作为能力放行面；C12.41 记录版本绑定。回指 L03.02 控制面纪律与 L02.02 能力闸门。
工程表达
判定句：硬编码直连模型 SDK 即违反网关收口。检查项：是否含版本绑定、故障转移、计量埋点与降级路径；不同计费口径是否被统一折算进 CPS。
L03.12
人机协同模式
核心洞察
对资金、权限、不可逆动作，人必须在环作为仲裁；协同分三档——人在环（HITL 可执行前确认）、人在上看（on-look 异常时介入）、人在外（off-band 仅审计），按动作后果分级，而非为减员而减员。
原理映射
MD notes 十「人机协同」与来源 A·十七；A07.01 / A07.02 四大风险面与分层防护把 HITL 列为可写工具必填项。回指 L01.04 人仍在环与 L02.08 组织治理（监督容量）。
工程表达
判定句：可写 / 高后果工具默认挂 HITL，确认界面须给检索依据、影响范围与回滚方式。检查项：是否定义三类协同边界与升级路径；确认上下文是否足以让人做裁决。
L03.13
多模态（文本/图像/音频统一表征与对齐）
核心洞察
多模态不是多路输入拼接，而是统一表征与模态对齐；文本/图像/音频各有失败模式，跨模态一致性要靠可验证的 grounding。
原理映射
回指 L03.17 证据绑定与幻觉防线、C12.10 多模态趋势、A09 检索进阶；与 L01.03 语义可观测衔接——多模态质量需语义级指标。
工程表达
判定句：多模态输出无跨模态一致性校验即视为未 grounded。检查项：图像/音频引用是否可溯源；模态对齐是否经评测；失败降级是否回退单模态。
L03.14
端侧与边缘部署（量化/蒸馏/端云协同）
核心洞察
端侧/边缘把推理下沉到设备，换来隐私、时延与离线，但受算力/内存/功耗约束；端云协同是关键——重模型在云、轻模型在端、上下文与缓存在端。
原理映射
回指 L03.10 缓存体系、L03.16 上下文预算、M09 容量评估、A18 部署形态；端侧隐私与 M13.04 数据保护、L02.14 合规本地化同构。
工程表达
判定句：端侧部署无模型量化/蒸馏与端云协同方案即视为不可生产。检查项：模型是否量化/蒸馏适配端算力；离线降级路径是否可用；端侧数据处理是否符合隐私边界。
L03.15
混沌与灾备
核心洞察
AI 系统须做语义故障注入（幻觉率飙升 / 注入攻击 / 工具超时 / 模型退役）演练降级与人工接管，并定义四维 RTO/RPO（算力、数据、模型、评估基线）——传统 HA 只看语法层存活，对语义失效盲区。
原理映射
MD 来源 A·十三「混沌、灾备」；A17.03 故障注入、A23.04 配置谱系与灾备把 ModelSBOM 列为灾备对象。回指 M09 混沌工程与 L03.01 回滚点（四方版本可回滚）。
工程表达
判定句：未跑过语义混沌演练不宣布高可用。检查项：四维 RTO 是否各自定义；退役模型是否移出活跃清单并保留带衰减 tile；演练是否含人工接管路径。
L03.16
上下文预算与压缩公式
核心洞察
上下文是硬预算，须按「可用窗口 − 系统提示 − 检索 − 工具结果 − 历史」分配；接近上界时触发压缩 / 摘要而非无限堆积。裸喂长上下文会放大矛盾、污染与幻觉。
原理映射
A08.04 上下文预算给出预算分配与压缩触发；A02.01 上下文工程定义分层状态。回指 L03.04 长链路步数预算与 L03.03 验证不可自证（摘要压缩会丢否定约束，须独立校验）。
工程表达
判定句：上下文超预算未压缩即触发降级，禁止裸喂长上下文。检查项：压缩是否保留否定约束与证据引用；风险标记是否跨轮继承；历史是否分片校验。
L03.17
证据绑定与幻觉防线
核心洞察
生成须绑定可追溯证据（文档 ID / 版本），用 NLI 矛盾检测与分层记忆做幻觉防线，而不是靠模型自述「我不确定」。无证据绑定的生成不得作为业务结论。
原理映射
A09.05 证据绑定要求生成带依据；A09.06 隔离把证据与生成解耦以防自证。回指 L03.03 验证不可自证与 L03.09 语义可观测准入（依据命中是准入指标）。
工程表达
判定句：无证据绑定的生成不得作为业务结论；矛盾检测失败即拦截。检查项：是否记录证据 ID 与置信边界；盲集复核是否定期跑；引用是否与原文对齐。
L03.18
记忆写入闸门与谱系（合并原 S14）
核心洞察
记忆写入等同生产变更，须过准入闸门（标准是「没有在别处制造退化」）并维护来源谱系；写入前治理（抽事实 / 去重 / 消解冲突 / 记来源）是把记忆腐化挡在门前的唯一手段。
原理映射
A02.04 记忆写入准入闸门与记忆谱系给出写入治理与拒绝策略；C12 记忆 / 向量章节提供落地。回指 L03.06 状态写入准入、L02.12 记忆生命周期、L01.06 语义时态。
工程表达
判定句：记忆写入未带来源谱系与失效信号即拒绝。划界：本卡只管「写入闸门 + 谱系」，D6 管「语义时态作为第一公民」，F12 管「腐化 / 遗忘权 / 继任的治理判定」。检查项：是否支持可验证删除与继任继承最严保留期。
L03.19
AI 资产退役标准作业（模型/知识库/记忆 无感下线 + 遗忘权销毁）
核心洞察
退役是生命周期末端却最易被忽略；模型/知识库/记忆的下线必须无感（调用方零中断）、可回滚、可审计；用户遗忘权要求数据真正销毁而非逻辑隐藏。
原理映射
回指 L02.01 五段框架（退役段）、L02.06 供应链与模型侧工程（退役窗口/组合版本/ModelSBOM）、L02.07 多租户隔离与资产退役、M05.14 系统退役标准、L03.18 记忆写入闸门与谱系。
工程表达
判定句：资产下线缺无感切换/回滚/销毁证明即视为违规退役。检查项：下线是否走影子/双跑再切流；遗忘权是否真删除并有证明；退役窗口与 ModelSBOM 是否更新。
L03.20
人在环模式目录（HITL pattern catalog）
核心洞察
人在环不是“人盯着”，而是分层的仲裁与兜底模式：审批闸（高风险动作前人工确认）、升级人工（模型不确定时转交）、人在环监督（抽样复核）、离环（全自动仅监控）；模式选择取决于风险×延迟×成本。
原理映射
回指 L01.04 人仍在环、L01.01 不确定性心智、L03.03 验证不可自证（人做独立验证）、L02.08 组织与变更治理、A26 组织 adoption；与 M14 复盘、M05.09 无责复盘衔接。
工程表达
判定句：高风险动作无对应人在环模式即视为缺兜底。检查项：每类风险动作是否选了正确的 HITL 模式；人工仲裁是否带上下文与可复核；规模化多 Agent 下监督瓶颈是否识别。
