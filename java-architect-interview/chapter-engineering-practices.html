工程化要点

把篇章 / 核心原理 / 场景导读里的「工程化要点」去重提炼为平台可执行门禁：发布回滚、可观测、容量、数据、缓存、调用治理、AI 评测、安全供应链八组共 24 卡。与方法论「怎么想」互补——本篇回答「不上线会出事的红线是什么」。

8 组 · 24 卡 | 不计入题目总量 365 | ID 前缀 G | 三层：洞察 / 原理 / 表达
门禁主线

每张 G 卡都按「可检查、可回滚、可观测」三问自检：没有证据链不上手段；没有回滚路径不上变更；没有卡点指标不扩量。

  1. 变更面：代码 / 配置 / 数据 / 模型与提示词，一律当发布。
  2. 容量面：应用池化与编排配额同一模型，拒绝路径可观测。
  3. 一致面：缓存窗口、双写 Outbox、对账任务写进契约。
  4. 智能面：制品版本化、黄金集回归、工具副作用分级。

发布回滚与变更门禁

G01.01
发布三要素：灰度·卡点·回滚架构级
核心洞察

高风险变更默认按「分批放量 + 指标卡点 + 一键回滚」执行；没有演练过的回滚路径等于没有回滚。

发布不是把包推上去，而是把爆炸半径可控地扩大，并在任一卡点失败时能退回已知好版本。灰度比例、卡点阈值、回滚命令三者缺一，变更单即不合格。

原理映射

对应 SRE 错误预算与金丝雀发布：流量/实例分批（如 1%→5%→25%→100%），卡点看错误率、延迟 P99、关键业务成功率，而非只看「进程起来了」。

配置、镜像、流量三维都要可退——只回滚代码却留下有毒配置，仍是事故。与方法论 M04.06 / M12.02 同构：回滚是默认能力，不是失败丢脸。

工程表达

变更单模板固定三要素并附：灰度比例表、卡点指标与阈值、回滚命令/开关、演练记录。卡点未过不得扩量；错误预算耗尽则冻结非紧急发布。

表达时先讲退路与观察窗口，再讲功能清单；被追问「出了问题怎么办」时，能当场指出回滚入口与 RTO。

G01.02
配置变更当发布架构级
核心洞察

热更新与配置推送必须按发布管控：审批、灰度、快速关停与本地快照兜底。配置中心一次全量推送，杀伤力往往大于发版。

「只改个开关」如果影响面是全集群，就必须走与发版同级的门禁。

原理映射

配置中心抖动不得拖垮核心链路：客户端要有本地缓存/快照、推送失败降级、订阅隔离。有毒配置（错误限流阈值、错误开关）要能秒级关停或回滚到上一版本快照。

与「配置即契约」（M12.09）一致：配置项的语义、默认值、生效范围写进契约，而不是口头约定。

工程表达

评审配置项时同步评审：生效范围、灰度策略、回滚开关、是否需要双写观察期。禁止生产控制台「随手改一把」；动态开关也要进变更单。

上线后核对：推送成功率、订阅滞后、关停演练记录。

G01.03
框架与依赖升级门禁架构级
核心洞察

大版本升级（Boot / Spring / JDK / 中间件客户端）用契约测试 + 金丝雀；弃用 API、默认行为变化、序列化/校验差异必须进回归清单。

「编译过了」不等于行为兼容——默认值、自动配置、校验顺序变化常在运行时才爆。

原理映射

基线 BOM 由平台抬升，业务少私锁版本，避免雪花版依赖。Breaking change 用兼容层或双跑；Native Image / AOT 场景还要覆盖反射与资源白名单。

安全补丁与功能升级分流：CVE 修复可快车道，但快车道仍需最小回归与可回滚镜像。

工程表达

升级门禁清单：契约测试（HTTP/消息/DB）、关键路径压测、金丝雀错误预算、回滚镜像就绪。私锁版本须说明退出计划与时间盒。

评审话术：「这次升级打破了哪些默认假设？」答不上来就补测试。

可观测与排障证据链

G02.01
三支柱默认交付架构级
核心洞察

日志规范、指标、追踪随脚手架默认接入，禁止上线后补丁式接入。没有证据链的系统，排障只能靠猜，变更只能靠赌。

可观测性是发布门禁的前置条件，不是增值选项。

原理映射

Logs / Metrics / Traces 互补：指标发现异常，追踪定位跨服务路径，日志给上下文。统一 TraceId 传播（含 MQ/线程池/定时任务）。

黄金指标按服务类型选型（RED/USE）；采样策略在成本与排障完整度之间显式权衡。与 M04.07、M12.01 同构。

工程表达

新服务 checklist：结构化日志字段、核心业务指标、入口/出口 span、仪表盘与告警模板。上线评审问「证据从哪来」，而不是「出了事再加」。

验收时抽一条真实请求：能否从入口 Trace 钻到依赖与日志。

G02.02
排障标准动作架构级
核心洞察

故障现场先止血再取证：保留现场（日志段、指标窗口、堆栈/转储、变更单），再离线分析。现场 debug 拉长 MTTR，是最大的反模式。

止血优先级通常是：回滚 > 降级 > 限流 > 扩容 > 重启 > 切流——按业务选，但必须事先写在 Runbook。

原理映射

标准动作链：分区归因（变更？流量？依赖？资源？）→ 采证 → 假设 → 验证 → 固化 Runbook。与线上问题主题 M10、证据优于经验 M12.01 对齐。

「感觉像是缓存」不算归因；归因要能指向证据时间线。

工程表达

排障话术固定四句：现象与范围、已采证据、当前假设、下一步与回滚条件。交接班必须移交证据包，不移交「感觉」。

复盘输出：时间线、根因、改进项负责人与截止日期。

G02.03
告警可行动高级开发
核心洞察

告警必须可行动：有明确责任人、有 Runbook、有抑制与聚合，禁止「只响铃不指向动作」。噪声告警会训练团队忽略真正的火情。

一条告警若从未被处理，就应从系统中删除或降级。

原理映射

告警设计看：症状（用户可感）优先于原因猜测；阈值与窗口防抖；夜间与工作时间分级。错误预算燃尽应触发发布冻结而非更多邮件。

关联告警聚合，避免同一根因打爆值班手机。

工程表达

每条告警附：影响面、首要动作、升级路径、相关看板。季度清理无主告警与从未处理的告警。

验收标准：新人按 Runbook 能独立完成首轮处置。

容量与资源预算

G03.01
应用与编排同一容量模型架构级
核心洞察

应用线程池/连接池/队列深度与 K8s CPU/内存/HPA 必须同一容量模型，禁止「应用按 QPS 估、编排按感觉设」。

两边不一致时，先打满的一侧决定真实容量——常见是池子先拒、或者 limit 先 OOMKill。

原理映射

容量=最小瓶颈资源。利特尔定律与排队论约束在途请求；容器 limit 与 JVM 堆、直接内存、线程栈要三联对齐。

HPA 指标要与业务饱和信号一致（CPU 不等于业务容量）。与 M06.07、M12.05 同构。

工程表达

容量文档写清：目标 QPS/RT、瓶颈资源、池化参数、HPA 阈值、拒绝行为。压测结论要能映射到编排参数变更单。

评审时现场核对：应用最大并发 × 单请求资源 ≈ 编排可提供资源。

G03.02
池化与拒绝可观测架构级
核心洞察

线程池、连接池、信号量的拒绝策略必须可观测：拒绝次数、队列等待、活跃数进指标与告警。静默拒绝等于悄悄丢业务。

拒绝是保护机制，必须让调用方与值班同时看见。

原理映射

Caller 需感知背压（快速失败/降级），Callee 需暴露饱和信号。虚拟线程场景仍要限制并发到下游，避免把压力打穿 DB。

队列从「缓冲」变成「延迟放大器」时，要下调队列、上调拒绝可见性。

工程表达

池化评审三项：核心/最大/队列、拒绝策略、指标名。压测必打到拒绝路径，确认降级文案与补偿。

上线后看板固定：拒绝 QPS、排队 P99、活跃线程/连接。

G03.03
大促前演练清单架构级
核心洞察

大促前必须做：全链路压测、限流阈值校验、降级开关演练、回滚演练、依赖容量确认。清单未勾完不上流量峰值。

演练的目标是暴露协同问题，而不是证明「没事」。

原理映射

演练重点：缓存击穿、热点账户、消息堆积、慢 SQL、线程池打满、依赖超时雪崩。错误预算与大促窗口绑定，发布冻结有明文。

依赖方容量函证要书面化，口头「应该扛得住」不算数。

工程表达

清单模板按「流量入口 / 核心交易 / 依赖 / 数据 / 回滚」五栏；演练结论进复盘，参数变更走发布门禁。

大促当天只允许预案内动作，禁止临时发明。

数据变更与 SQL 治理

G04.01
DDL/数据修复可回滚架构级
核心洞察

DDL 与数据修复必须可回滚或可正向补偿：影子表、双写、分批、回填校验。不可逆删改默认禁止在高峰直打生产。

数据变更与代码变更同等危险，经常更危险。

原理映射

在线 DDL 看锁与复制延迟；大表变更用 gh-ost/pt-osc 或云厂商在线变更。数据修复先备份/抽样校验，再全量。

与「变更可回滚」M12.02 一致：回滚方案写不清，变更单退回。

工程表达

变更单附：执行窗口、回滚 SQL/切流方案、校验查询、影响行数预估。禁止「先删后说」。

执行中盯复制延迟与锁等待；超阈熔断执行。

G04.02
SQL 审核与慢 SQL 闭环架构级
核心洞察

SQL 必须过审核（索引、回表、临时表、大偏移）；慢 SQL 要有发现→归因→修复→回归的闭环，而不是只调大超时。

超时调大是推迟爆炸，不是治理。

原理映射

审核关注：选择性、覆盖索引、分页策略、N+1、隐式转换、深分页。慢日志与 apdex 联动；修复后用相同流量形状回归。

从库「看起来快」不能代替主路径 explain。

工程表达

上线门禁：新增 SQL 有 explain 结论；慢 SQL 工单有负责人与截止日期。表达时能讲清「为什么走这条索引」。

回归报告附：修复前后 RT/扫描行数对比。

G04.03
扩展前先单机架构级
核心洞察

分库分表、读写分离前先压榨单机：索引、SQL、缓存、批量、异步。过早拆分把复杂度前置，却不一定换来容量。

拆分是架构税，要用证据证明值得交。

原理映射

与 M12.10「扩展前先单机」同构：先证明瓶颈在容量而非实现。拆分后的事务、对账、路由、热点成本要写进架构决策记录（ADR）。

工程表达

扩展评审先出示单机优化前后对比与瓶颈证据；拿不出证据不批准拆分。

批准后的第一期目标是「可回滚的路由与对账」，不是「一次拆完美」。

缓存一致与热点治理

G05.01
缓存失败可降级架构级
核心洞察

缓存穿透/击穿/雪崩与缓存集群故障时，必须有降级：回源限流、默认值、只读旧数据、熔断依赖，禁止无限回源打穿 DB。

缓存挂了系统仍应「降级可用」，而不是「更不可用」。

原理映射

缓存是加速器不是真相源（M12.11）。失败模式要在设计期声明：一致性窗口、过期策略、互斥重建、布隆/空值缓存。

多级缓存要定义失效顺序，避免击穿层层放大。

工程表达

故障演练必做「缓存全挂」：观察 DB QPS 与用户可感错误率，确认限流与降级开关有效。

Runbook 写清：何时开降级、何时允许回源、何时止损回滚。

G05.02
一致性窗口写进契约架构级
核心洞察

缓存与 DB 的一致性不是「最终会一致」一句话，而要写成契约：窗口时长、读路径（主/从/缓存）、用户可感语义。

窗口内允许什么、不允许什么，产品与研发必须同一张纸。

原理映射

常见策略 Cache-Aside / Write-Through / 延迟双删各有代价。窗口内允许脏读必须产品知情；金融类往往要求绕过缓存读主。

与 M12.11 / M12.12 一致：先定一致模型，再选组件。

工程表达

接口文档与 SLA 写明一致性窗口；排障时先问「用户读的是哪条路径」。

变更缓存策略视为发布，走灰度与回滚。

G05.03
热 key / 大 key 专项架构级
核心洞察

热 key 与大 key 必须专项治理：拆分、本地缓存、复制、压缩、拆 value。热点会把集群变成单点。

大促前不知道热点在哪，等于不知道单点在哪。

原理映射

发现靠：代理层热点统计、大 key 扫描、慢查询。治理按「打散」：哈希标签、分片、多副本只读。与高并发热点方法论 M06.06 对齐。

工程表达

大促前出热点清单与预案；上线后持续扫描，超阈进工单。

验收：热点 key 的单分片 CPU/QPS 不再独占集群。

调用预算与服务治理

G06.01
同步链路预算入契约架构级
核心洞察

同步调用链的超时必须可加总：各跳超时之和小于用户超时，并留重试与排队余量。无预算的超时=随机故障。

超时是分布式系统的第一公民，不是调优参数。

原理映射

超时、重试、幂等、熔断一起设计：重试无幂等会放大写；熔断阈值要基于错误类型而非笼统 5xx。与 M12.03 超时预算同构。

取消（cancellation）要能向下传递，避免下游空转。

工程表达

链路预算表进架构文档：每跳 RT P99、超时、重试次数、幂等键。评审时现场加总。

压测验证：某一跳变慢时，整链失败模式符合预期而非雪崩。

G06.02
治理参数可回滚架构级
核心洞察

限流/熔断/降级参数变更按发布管控，必须可回滚。错误的限流阈值可以制造「自攻」——把正常流量挡在门外。

治理参数与业务开关一样危险。

原理映射

治理参数进配置门禁；变更前后对比错误率与通过率。集群限流与单机限流语义要分清，避免「每实例都以为自己是全集群」。

工程表达

参数变更单含：旧值、新值、观察指标、回滚条件。禁止高峰临时「拍脑袋调大」。

演练：错误参数一键退回的时间要进入 RTO。

G06.03
双写用 Outbox/CDC架构级
核心洞察

消息与 DB 双写禁止「先发消息再写库」无补偿；用 Outbox / CDC / 事务消息保证至少一次投递后的可对账。

双写是分布式一致的经典陷阱，必须有模式而不是有感觉。

原理映射

最终一致三件套：幂等消费、可重试、对账（M12.04/M12.12）。CDC 要注意顺序与表结构变更兼容；乱序要有版本或聚合键。

工程表达

双写方案评审必问：失败怎么补偿、重复怎么消化、对账任务谁跑、对账差异怎么修。说不清则退回同步或单写。

上线后对账任务进值班看板。

AI 制品与评测门禁

G07.01
制品全版本化架构级
核心洞察

Prompt、模型 ID、检索配置、工具实现、编排图全部版本化，可对齐回放与一键回退；版本号进日志与审计。

AI 变更面远大于普通服务，版本化是唯一可回放手段。

原理映射

温度、切片、重排、工具副作用任一变化都视为发布。与 M12.14 同构：AI 变更必回归。多模型路由策略也要版本化。

工程表达

发布清单含：模型版本、提示词哈希、索引版本、工具契约版本。回滚能指到具体制品，而不是「再调一下」。

审计：任一线上回答能追溯到制品组合。

G07.02
无黄金集不上线架构级
核心洞察

任何改动必须过固定黄金集/测试集回归；无测试集不上线。离线指标 + 小流量线上数据双确认后再全量。

个例体验不是评测，是采样偏差。

原理映射

评测集覆盖：正确性、拒答、安全、工具调用、延迟与成本。集合要冻结版本，防止「改题迎合模型」。

工程表达

门禁：黄金集通过率阈值、回归报告链接、灰度观察看板。未达标不得扩量。

表达：先报评测数字，再报主观体验。

G07.03
工具副作用分级架构级
核心洞察

Agent 工具按副作用分级：只读 / 可重试写 / 不可逆写；不可逆写必须人工确认或强幂等键。

工具是带权限的远程代码，不是聊天点缀。

原理映射

工具契约含：权限、超时、幂等、审计。提示词注入与越狱防护与工具暴露面一起评审；最小权限默认。

工程表达

上线前列出工具清单与级别；不可逆写默认关闭或双人复核。表达时能讲清「最坏能写坏什么、怎么回滚」。

演练：恶意/越权调用是否被挡。

安全运营与供应链

G08.01
威胁建模先行架构级
核心洞察

安全需求在设计期做威胁建模（STRIDE 等），而不是上线后补扫描。假设组件会被攻破，问「破了是否仍可控」。

安全是约束，不是功能清单。

原理映射

与 M09 纵深防御同构：最小权限、失败安全、零信任。数据流图上标信任边界与敏感数据；残余风险显式接受或关闭。

工程表达

方案评审附威胁模型一页纸：资产、威胁、缓解、残余风险。高风险项未关闭不得上线。

复盘安全事件时回指威胁模型缺口。

G08.02
密钥证书可轮换架构级
核心洞察

密钥与证书必须可轮换：双密钥并存窗口、自动续期、吊销流程。写死在镜像里的密钥是定时炸弹。

不能轮换的密钥，等于不能响应泄漏。

原理映射

密钥分级：应用密钥、数据密钥、根密钥；HSM/KMS 托管。证书过期监控与告警可行动；吊销名单要真能拦住流量。

工程表达

轮换演练每年至少一次；变更单含吊销与回滚。禁止共享账号长期静态口令。

验收：泄漏演练中能在约定 RTO 内完成轮换。

G08.03
依赖与镜像可追溯架构级
核心洞察

依赖与镜像必须可追溯：SCA 扫描、SBOM、签名/哈希校验、基础镜像基线。供应链失败按生产事故定级。

「不知道跑了什么」比「有个 CVE」更危险。

原理映射

构建可复现、制品签名、部署校验。第三方调用校验证书并设超时。与安全手册供应链章节对齐；高危 CVE 有豁免流程与截止日。

工程表达

门禁：高危 CVE 阻断、SBOM 归档、镜像来源白名单。表达时能指到「这个包从哪来、谁签的名、何时扫的」。

抽查：任一生产镜像能还原构建与依赖树。
