一、核心方法论（道法术势，M01-M16）

两公理是一把钥匙：所有性能问题=资源竞争，所有可用性问题=单点故障——三高不可能三角由此推出，全部方法论由此展开。

层级自检：换行业仍成立→道；能画阶段/责任表→法；要调参→术；能安装替换→器；阻力来自人/时机→势
取舍三句话：选了什么/放弃了什么/为什么值得——每个方案必答
演进两元操作：加法换能力、减法做熵减；每迭代留 10-20% 还债配额
代价转移五字诀：分合增减转——复杂度守恒，只能转移不能消灭
定性定量六步：定性定方向→基线→定量目标→改造→验证→复盘；无基线不优化
故障前置六问：单点/一致性/流量突增/回滚/降级/可观测
Goodhart/Hyrum：指标一旦成目标即失效；所有可观察行为终将被依赖
康威定律：系统结构=组织沟通结构；逆康威先设计目标团队再落地架构
面向失败六层递进：超时→重试幂等→限流→熔断→降级→隔离，层层设防
线程池公式：CPU 密集型=核数+1，IO 型=核数×(1+等待/计算)
变更分级三维：影响面×可回滚性×是否数据变更，定级决定审批链
排障证据链：现象→归因→jcmd/MAT/日志，无证据不改参

M06 运行时架构原则
面向失败六层递进：超时→重试幂等→限流→熔断→降级→隔离
迟滞阈值+稳定窗口：防扩缩容震荡与告警风暴双保险
隔离三型：故障/资源/数据；无界队列是隔离天敌
无状态优先：状态外置 Redis/DB，扩展与发布自由前提
回滚三件套：可回滚+可灰度+可监控，缺一不上线
可观测三支柱：Prometheus/ELK/SkyWalking，traceId 全链路关联
泄漏信号速查：FD 30 分钟单调涨、CLOSE_WAIT>20%、池 waiting>0；池 max≈下游可承受×0.8
Fail Fast 四防线：输入/组件/时间/并发，try-with-resources
M07 分布式心智
一致性三问：容忍旧值多久？允许重复还是丢失？强一致还是 Saga？
故障域≤冗余度：N−1 原则，冗余必须覆盖最大故障域
缓存非源四档：强一致不缓存/TTL≤1s；准实时 1~10s 或 CDC；最终一致分钟级+对账
缓存参数速查：TTL 随机 ±10% 防雪崩、空值≤60s、互斥重建≤200ms、单 key>5000 上多级
事务选型：优先最终一致（本地消息表/Saga/TCC）；XA 最后手段；补偿前提=幂等
八大谬论：网络可靠/延迟为零/带宽无限/网络安全/拓扑不变等
远程调用代价：比本地慢 3~6 个数量级，设计先算调用次数
M08 高并发与吞吐
拆分顺序：动静分离→读写分离→负载均衡→分库分表→异地多活（AKF 三轴）
拆分阈值：QPS 破 5000 分库分表，破 5 万异地多活
分片前置：单机写>5000 TPS 或单表>2000 万行即规划分片
慢 SQL 判据：long_query_time=0.1s；rows_examined/sent>100=索引失效
背压：宁可快速失败不无界缓冲；线程池拒绝策略本质=背压
背压断裂信号：队列 5 分钟单调涨+内存涨而错误率不升；MQ prefetch 默认 256
热点治理三层：识别→拆散→削峰；单账户 3 万 TPS 拆 16 影子子账户
线程数公式：CPU 密集≈核数；IO 密集=核数×(1+等待/计算)，×2~4 起步压测
利特尔定律：L=λ×W；200 线程×0.2s=1000 QPS，反推容量与扩容
M09 高可用与可靠
可用性公式：A=MTBF/(MTBF+MTTR)；99.9%=月 43 分钟错误预算
多活分级：冷备→热备→主从→双活→多活；峰值水位<70%
限流四算法：计数器→滑动窗口→漏桶→令牌桶，按精度递进
熔断三级联防：Nginx→网关(Redis+Lua)→Sentinel，网关阈值>应用×实例数
容灾递进：冷备→同城双活→异地双活→两地三中心；Binlog 同步≤50ms
容量五步压测：染色→影子隔离→Mock→梯度加压（错误率>0.1% 或 RT 翻倍即停）→建模留 30% 冗余
冗余与共识：Raft 多数派 N/2+1；3 副本容忍 1 故障性价比最高
混沌实验四步：定稳态→假设→注入→证伪；稳态异常自动回滚
M10 高性能与延迟
四类等待四条路径：CPU→火焰图；IO→慢查询；锁→线程 dump 看 BLOCKED；GC→GC 日志
目标函数先行：延迟/吞吐/足迹不可兼得；低延迟=G1/ZGC+MaxGCPauseMillis
GC 基线四指标：暂停 P99、gc.time/wall_time、分配速率、晋升速率
分层 ROI：架构层 10 倍→系统 2-5→应用 2-3→代码 1.5→JVM 1.2 倍；一个缓存可能胜过所有 JVM 调优
延迟阶梯：L1 纳秒→内存 ~100ns→SSD ~10μs→磁盘 ~10ms→网络 50ms+
命中率红线：Buffer Pool<95% 先优化索引，别急着加机器
缓存三问题：穿透→布隆/空值；击穿→互斥锁；雪崩→随机 TTL/多级
存储引擎选型：B+Tree=OLTP；列存=OLAP；LSM=写多读少
优化五步：测量→假设→实验→验证→回归，禁无测量优化
M11 变更与副作用纪律
预算冻结线：燃尽率>2 倍预算/天即冻结发布
灰度节奏：1%→10%→50%→100%，每档≥30 分钟观察
回滚时长目标：配置≤1 分钟、镜像≤5 分钟；回滚演练每季度
幂等键构成：业务类型+业务主键+请求摘要；去重窗口≥24h~7d
重试纪律：指数退避+抖动，上限 3~5 次，(n+1)×timeout≤上游超时
超时链递减：客户端 3s>网关 2.5s>服务 2s>单跳≤500ms，各跳留 20% 余量
对账三档：T+1 全量/准实时 5-10 分钟（金额类）/实时逐笔
对账告警阈值：金额类差异率>0.01%、非金额>0.1% 即告警
差错红线：先冻结争议单再冲正，禁止直接改余额
M12 Java 生态心智
并发优先序：不可变>并发集合>无状态设计>手工加锁；业务池与 IO 池分离
三性排查模板：i++/check-then-act=原子性；无 volatile=可见性；DCL 漏 volatile=有序性
工具速查：LongAdder 写多场景；JEP 491 synchronized 不再 pin 虚拟线程
JVM 排查四件套：GC 日志、堆转储、JFR、JMC，数据驱动而非玄学调参
OOM 五落区：堆/元空间/直接内存/栈/线程，先问落哪个区
容器参数：-Xmx=limit 的 70% 或 MaxRAMPercentage=70
OOMKilled exit 137：容器层拿不到堆转储，先核对 limit 与 RSS 差值
事务失效三查：private/final 方法、自调用绕过代理、默认只回滚 RuntimeException
Spring 配置优先级：命令行>系统属性>环境变量>外部配置>application-{profile}
M13 安全工程心智
四原则+零假设：最小权限/零信任/纵深防御/安全左移；假设每个组件都会被攻破
纵深四道：认证授权→会话管理→输入验证→输出编码；白名单优先
注入防护：SQL 一律 #{} 禁 ${}；SameSite+CSRF token；输出按上下文编码
口令哈希链：Argon2id>scrypt>bcrypt(cost≥10)>PBKDF2(≥600000)；禁 MD5/SHA-1
认证协议：OAuth2 授权码+PKCE；JWT 显式算法防 alg=none、access_token 15min
密钥生命周期：生成→HSM/KMS→90 天轮换→销毁全托管
加密选型：AES-GCM 禁 ECB；RSA-OAEP≥2048；SHA-256/3；SecureRandom；TLS≥1.2 优 1.3
后量子迁移：ML-KEM/ML-DSA（FIPS 203/204），2030 年前完成迁移规划

M15 排障与复盘
止血优先序：回滚>降级>限流>扩容>重启>切流量；先保留现场再离线分析
证据链标准：错误率看 5 分钟粒度；火焰图采样≥60s；堆转储取 OOM 前+现场两份
对照实验：观察≥30 分钟；样本量 n≥(1.96σ/Δ)²
四步闭环：止血→定位→根因（5Whys）→复盘（blameless，改进项带 owner+期限）
5Whys 红线：根因指向流程/系统缺陷，不许落在人疏忽
自愈边界：网络抖动/OOM/依赖超时可自愈；DB 主从切换/数据损坏必须人工
可观测分工：Metrics 答发生了什么、Tracing 答在哪里、Logging 答为什么
时间线硬指标：3 分钟响应→止血→留现场→24h 复盘→混沌演练验证；盯 MTTD/MTTR

二、工程化要点 + 生产踩坑（G01-G08 / K01-K08）

两条主轴贯穿全部门禁：卡点指标分层——L1 用户可感 > L2 依赖饱和 > L3 资源，L3 不能单独放行；回滚三维——镜像+配置+流量，任一不可退则整体不可退。

发布三要素缺一不合格：灰度比例表+卡点指标阈值+一键回滚命令

超时×重试必须有上限：否则调用放大打穿下游
幂等键持久化+TTL：防重复扣款的第一道防线
缓存三防：穿透（空值缓存）、击穿（逻辑过期）、雪崩（随机 TTL）
容量对齐：连接池与 K8s limit 一致，不一致即假可用
门禁不是流程负担：是把踩坑成本前置支付的保险

三、场景设计框架（S01-S12）

所有场景共用一个骨架：漏斗思维——流量逐层拦截衰减，DB 永远只接最后一层；量化阈值——每个方案必答「当前量级用什么、超过什么阈值演进什么」。

漏斗分层数字：CDN/Nginx 拦大头→网关限流→Redis+MQ 削峰→DB 只接最后一层
防超卖：Redis Lua 原子扣减，DB UPDATE...WHERE num>0 兜底
热点治理：库存分桶打散 key、推送聚合批播、记账分离只写流水表
缓存一致性：先 DB 后删缓存、延迟双删/binlog 订阅、对账任务兜底
高可用四件套：限流、熔断（Closed→Open→Half-Open）、降级、隔离
分布式事务：本地消息表/SAGA 优先，2PC 性能差是反面教材
分布式锁选型：Redis AP 高性能、ZooKeeper CP 强一致，按场景定
全链路压测：影子库表隔离+流量标记透传，找出瓶颈定安全水位
AI 场景：RAG=切分+向量检索+重排+引用溯源；评测集必须版本管理
表达顺序：先给数字与漏斗，再谈组件选型，最后给演进路径

S01 高并发系统设计
漏斗模型：120 万 QPS 按 CDN/Nginx 拦 70%→网关限流拦 20%→Redis+MQ 削峰 9%→DB 仅放行 1%
防超卖：Redis Lua 原子脚本一次完成去重+扣减，禁先查后扣；DB UPDATE...WHERE num>0 兜底
库存分桶：1000 件拆 10 桶打散热点 key，单桶压力降 10 倍；Redis vs DB 定时对账
短链架构：发号器号段双 buffer+62 进制转码；BloomFilter(误判 0.01%)→Redis→DB 三级拦截 99% 穿透
短链存储：1024 库×4 表=4096 分片；防删除误判用 CuckooFilter
红包拆分：二倍均值法预拆存 Redis List，LPOP O(1) 原子弹出+MQ 异步入账
弹幕聚合：每 200ms 聚合一批（≤50 条）批量广播，推送量降 50 倍
在线统计：HyperLogLog 12KB 算亿级基数误差<1%，禁 SET；心跳 60s 随机抖动
热点账户：记账分离只写流水表，100ms 窗口聚合净额批量 UPDATE（3 万 TPS→约 10）
S02 分布式系统
分布式锁选型：性能优先 Redis（SET NX PX+Lua 释放+看门狗）；强一致选 ZK/etcd（fencing token）；Redlock 慎用
锁三要素：互斥、防死锁（必须持有时间）、可重入（Hash 记 threadId）；释放 Lua 比对 value 防误删
事务选型：强一致 TCC/XA；最终一致 Seata AT/本地消息表/事务消息；TCC 防空回滚与悬挂
Seata 坑：RPC 未传 XID 回滚失效；TCC 未幂等重复扣
分布式 ID：雪花处理时钟回拨与 workerId 分配；号段双 buffer 防断供
雪崩三道防线：熔断降级+线程池隔离（舱壁）+入口限流；链路追踪定位最慢节点
缓存一致性：Cache Aside 写库后删缓存（非更新）；延迟双删+Canal 订阅 binlog
幽灵通知：事务内禁直接发通知，用 afterCommit 提交后才发；强可靠上本地消息表
通知口诀：提交才发、回滚不发、参数闭包、强可靠上消息表
S03 数据库与存储
分库分表六步：容量评估（3 年量、2 的幂）→选分片键（user_id 基因法）→倍增扩容→影子双写→diff 校验→灰度切读
分片键红线：表数必须 2 的幂（否则扩容全量重分布）；先单机挖尽再拆
慢 SQL 闭环：慢日志+APM 抓 Top10→EXPLAIN→优化优先级 SQL 重写>索引>表结构>架构
深分页：延迟关联或游标分页；LIKE 前导 % 失索引
主从延迟：区分 IO/SQL 线程延迟；强一致读走主库；8.0 WRITESET 并行复制
缓存三问题：穿透→布隆+空值；击穿→互斥+逻辑过期+预热；雪崩→TTL 随机+多级+降级
海量小文件：对象存储替代 HDFS；日志 128MB 合并 Parquet 入湖；生命周期分层
对象存储红线：公网直连有费用+安全风险须走网关收口
S04 微服务架构
拆分方法论：事件风暴识别限界上下文，按领域拆；绞杀者渐进+网关切流；同步链路不超 3 跳
拆分陷阱：共享 DB 未做访问隔离；拆完必须灰度切流不直接全量
网关选型：SCG（WebFlux 异步）+责任链+Sentinel+Nacos 动态路由；网关只做接入不做业务
MQ 积压四步：扩容（消费者≤分区数）→批量/异步化→应急跳过+扩分区→治理（手动 ACK）
灰度发布：X-Gray-Tag 全链路透传+Nacos metadata 路由+影子库隔离；回滚靠路由 30 秒切换
Service Mesh：Istio+Envoy；与 Spring Cloud 双注册共存渐进迁移
配置热更新事故：@RefreshScope 懒重建旧 target，单例强引用导致双实例/泄漏/定时任务重复
配置口诀：配置用 POJO、字段实时取、@RefreshScope 只救 @Value；线程池先 shutdown 旧再建新
S05 性能与稳定性
OOM 五步：现象→归因（泄漏 vs 溢出看 GC 斜率）→证据（Arthas）→根因（MAT Dominator Tree）→JFR 观测 24h
OOM 红线：预配 HeapDumpOnOutOfMemoryError；不摘流量直接 dump 触发长 STW
CPU 100% 四层下钻：top→top -Hp→线程 ID 转 16 进制→jstack 3 次快照 grep
接口优化 200ms→20ms：画链路找 Top3 瓶颈；缓存>并发>批量>索引；CompletableFuture 并行+超时
消息可靠性三段：生产本地消息表；Broker 同步刷盘+复制+分区保序；消费幂等表+手动 ACK
幂等坑：先删标记再执行业务会重复；幂等键禁易变参数；全局有序是伪需求
全链路压测：流量染色影子库+Mock 挡板；Little's Law+排队论；梯度加压+自动熔断
线程池选型：动态调参池做内核+Spring Bean 暴露；快慢任务分池；虚拟线程仍要背压
S06 云原生与 AI
虚拟线程落地：用户态调度只适合 IO 密集；synchronized 换 ReentrantLock 防 pinning；ThreadLocal 改 ScopedValue

S07 综合场景

S08 高可用架构
异地多活：单元化按 userId 固定落单元+binlog 闭环+Fencing 租约防脑裂；RTO<1min、RPO=0
限流熔断体系：入口限流+链路熔断+依赖隔离（舱壁）+降级兜底；线程池配额按 Little's Law
混沌工程五原则：稳态假设/贴近真实/持续/自动化/最小爆炸半径
故障自愈：感知→决策→执行→恢复；宁可慢摘不可误摘；保留人工一键熔断
容量水线四级：安全 60%/预警 70%/限流 85%/熔断 95%；链路可用性是乘积
可观测三支柱：OTel 统一埋点→全程透传→关联分析→告警分级聚合（目标误报 -80%）

S09 安全架构
纵深防御四层：WAF→Nginx→应用层→数据层；仅靠 WAF 可绕过，应用层必须兜底
注入坑：MyBatis ${} 即使 ORDER BY 也可注入（白名单映射）；富文本按字段差异化净化
API 安全：OAuth2+PKCE+refresh 轮换+JWT RS256+HMAC 签名+timestamp/nonce 防重放
信封加密：DEK/KEK 双层，KEK 存 KMS 永不离开；等值查询用确定性加密
权限双层：RBAC 功能权限+数据权限（拦截器自动注入 WHERE）；默认拒绝
越权双防：垂直+水平都要防；禁信任前端 userId
数据合规：Privacy by Design 全生命周期；删除覆盖 ES/Redis/备份；测试禁生产快照
S10 网络 IO
Netty 网关：池化 ByteBuf+Boss/Worker 分工+一致性哈希分片；单机 10 万连接
Netty 坑：不关 TCP_NODELAY 延迟 40ms（Nagle）；EventLoop 里执行业务逻辑假死
TCP 粘包：自描述帧（Magic+LengthField+CRC）；LengthFieldBasedFrameDecoder；非法长度帧关连接
协议选型：HTTP/2（浏览器）→gRPC（内部）→QUIC（弱网试点）；protobuf 字段号只增不改
WebSocket 推送：无状态集群+Kafka 广播+分级路由（tick/1s/5s）；心跳 30s 与 Nginx 超时 90s 错开
连接池调优：三级超时分级、各下游独立配置；maxTotal 过大致下游连接暴涨
S11 搜索与大数据
ES 集群：时间拆索引+热温冷分层+Bulk 批量；深分页 search_after 替代 from+size
搜索推荐五层漏斗：意图识别→多路召回→粗排→精排→重排；防特征穿越

C01 JVM 内存与类加载
运行时数据区：线程私有=栈/程序计数器；共享=堆/元空间/直接内存；OOM 类型按区域对应
Metaspace：MaxMetaspaceSize 必须显式设（256-512m），否则无限增长吃本地内存

对象内存：压缩指针下对象头 12B；堆≥32G 压缩指针失效，单实例建议 -Xmx31g
类加载五阶段：加载→验证→准备→解析→初始化；双亲委派=安全+类唯一性

一条总纲统领全部检查点：默认不信任——输入走白名单校验、权限最小化、密钥不出 KMS、出口一律加密与脱敏。

认证与授权
口令哈希：Argon2id 首选/scrypt/bcrypt(cost≥10)/PBKDF2(≥210000)，禁 MD5/SHA-1
salt：每用户唯一随机，禁全局共享或无 salt

IV/Nonce：每次随机唯一，禁固定复用；GCM 校验失败必须拒绝
