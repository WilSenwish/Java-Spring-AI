# 01 概念边界与战略逻辑

> 本文回答：信创是什么、不是什么；它与「国产化」「自主可控」「安全可靠」等高频概念如何区分；国家推进这件事的底层逻辑是什么；以及理解时应持有哪些多视角框架。

## 1. 术语溯源与定义

### 1.1 「信创」一词的来源

「信创」是**信息技术应用创新**的简称，其直接词源是 **2016 年 3 月成立的中国电子工业标准化技术协会信息技术应用创新工作委员会**（简称「信创工委会」）〔证据等级 B，多源一致；工委会成立年份与名称在行业协会资料、百科类资料中一致〕。

这一点有两个容易忽略的推论：

- 信创**不是法定术语**。在国务院、财政部、国资委的正式文件中，使用的是「本国产品」「自主创新产品」「安全可靠」「产业链供应链安全」「信息技术应用创新产业」等表述，极少直接以「信创」作为法律概念。
- 信创是一个**产业与工程概念**，其内涵随实践演进：早期近似「安可（安全可控）替代」，中期扩展为「2+8+N 行业国产化」，2023 年后进一步扩展为全栈自主可控 + 生态构建 + 价值替代。

### 1.2 工作定义

综合政策文本与产业实践，给出可操作的工作定义：

> **信创**是指在关系国家安全与国民经济命脉的信息系统领域，以**自主可控、安全可靠、生态协同**为目标，通过基础硬件、基础软件、应用软件、信息安全与云平台的体系化替代与重构，建立可验证、可审计、可持续演进的国产信息技术供给体系，并以标准、测评、采购、工程方法予以制度化的过程。

定义中有三个不可省略的限定：

1. **限定领域**：不是全社会所有 IT 采购，而是关键领域、关键信息基础设施、党政与重点行业。边界问题见 §5.4。
2. **限定目标**：不是「国产」二字本身，而是可控、可靠、可持续。国产只是手段之一。
3. **限定为过程**：包含制度（标准/测评/采购）与工程（适配/迁移/验证），不只是产品清单。

## 2. 概念族辨析

这是全站最容易被混用的一组概念。下表按「评价对象」与「回答什么问题」区分：

| 概念 | 评价对象 | 回答的问题 | 主要依据 | 常见混淆 |
|---|---|---|---|---|
| **国产化替代 / 信创替代** | 采购与部署行为 | 是否把国外产品换成了国内供给 | 采购合同、适配清单 | 被当作合规结论 |
| **自主可控** | 技术与供应链 | 关键技术是否受制于人、断供后能否持续演进 | 知识产权归属、授权链路、代码自主率、供应保障 | 与「国产」划等号 |
| **安全可靠** | 产品 + 研发单位 | 全生命周期安全性与可持续性 | 《安全可靠测评工作指南 V3.0》及测评公告 | 被误解为等保等级 |
| **本国产品** | 具体货物 | 是否满足政府采购的本国产品标准 | 国办发〔2025〕34 号 | 被误解为「国产 CPU 强制令」 |
| **自主创新产品** | 产品 | 是否属于国家支持的自主创新成果 | 「十五五」规划建议、相关采购政策 | 与「本国产品」混用 |
| **等保 2.0** | 信息系统 | 系统整体防护是否达标 | GB/T 22239-2019 | 与产品测评混淆 |
| **密评** | 密码应用 | 密码算法/产品/密钥管理是否合规有效 | 《密码法》第 27 条、GB/T 39786-2021 | 被当作等保子集 |
| **安可（安全可控）** | 历史阶段性表述 | 2014—2019 年前后的替代工程口径 | 早期试点文件 | 被当作现行正式概念 |
| **信息技术应用创新产业** | 产业 | 供给侧厂商与产值集合 | 研究机构产业分类 | 与「安可产业」口径不一 |

**关键区分**：

- 「本国产品」是**产地与成本比例**概念（34 号文），「自主可控」是**技术与供应链**概念，「安全可靠」是**产品与厂商综合能力**概念。三者可以同时成立，也可以互不包含：一款在中国境内组装、组件成本达标的外资品牌服务器，可以是「本国产品」，但未必「自主可控」；一款自主指令集 CPU 可以「自主可控」，但若未送测则不在安全可靠测评结果公告内。
- 等保与密评评的是**系统**，安全可靠测评评的是**产品及其研发单位**，适配认证评的是**组合兼容性**。四套体系并列，详见 [06](./06-安全合规与测评认证体系.md)。

## 3. 三层内涵

### 3.1 自主可控：控制权而非产地

中国工程院倪光南院士在 2016 年的公开论述中给出过一个至今仍有效的判断：供应链任一环节不能自主，就不满足自主可控；对 CPU 而言，即便设计不受制于人，若生产必须依赖境外，仍不达标；他还批评了以「境内注册 + 缴税」或「生产成本占比 50%」判定国产的做法，认为高技术产品成本主体是智力成本，生产成本准则会为「贴牌」留出空间，并建议参考美国《购买美国产品法》的「增值」准则〔证据等级 B，人民日报《中国经济周刊》2016-04-18〕。

这段论述对理解 2025 年 34 号文有直接价值：**34 号文采用的是「属性改变 + 组件成本占比」的路径，而非「增值/自主知识产权」路径**，并额外对特定产品保留「关键组件、关键工序」要求，用 5 年时间分产品制定比例、设置 3—5 年过渡期。也就是说，制度设计者清楚「境内生产」不等于「自主可控」，因此把两者拆成两套独立工具：34 号文管政府采购的产地与成本标准，安全可靠测评管核心产品的技术与供应链可靠性。

### 3.2 安全可靠：全生命周期能力

《安全可靠测评工作指南 V3.0》的定义是：对产品及其研发单位的**核心技术、安全保障、持续发展**开展评估，评定产品的**安全性与可持续性**，实现对研发设计、生产制造、供应保障、售后维护等全生命周期安全可靠性的综合度量〔证据等级 A，中国信息安全测评中心官网表述，经多份公告与指南转述一致〕。

注意「研发单位」与「持续发展」两个关键词：测评不是单纯的产品功能测试，而是把厂商组织能力、迭代路线、漏洞响应、供应链韧性纳入评价。这解释了为什么测评结果设 **3 年有效期**——迫使厂商持续投入而非「拿证躺平」。

### 3.3 生态协同：从单品到系统

产业实践反复证明：单点产品达标不等于系统可用。典型表述是「单品追赶、系统领先」「走出组合式加法，走向适配式乘法」〔证据等级 C，行业媒体与上市公司公告表述〕。生态协同包含三层：

- **纵向**：芯片 → OS → 数据库 → 中间件 → 应用 的联合调优（而非逐层拼装）。
- **横向**：同一层多技术路线共存时的兼容性治理（一云多芯、多架构镜像、统一云管）。
- **时间维度**：版本迭代后适配关系不失效，需要持续回归测试与认证有效期管理。

## 4. 战略逻辑：为什么要做

### 4.1 安全维度：三类风险

| 风险类型 | 具体表现 | 制度回应 |
|---|---|---|
| **断供风险** | 出口管制、实体清单、授权终止、代工产能受限 | 834 号令关键领域清单、多元供应渠道、安全可靠测评「供应保障」维度 |
| **后门与预置风险** | 闭源组件不可审计、固件/驱动层不可控 | 网络安全审查、关基条例、源代码审查类测评环节 |
| **运行风险** | 停服（如 CentOS）、补丁收敛、老旧版本维保成本上升 | 迁移窗口、国产 OS 替代供给、SBOM 与漏洞治理 |

历史触发点构成清晰链条：2006 年「核高基」专项 → 2008 年微软「黑屏」事件 → 2013 年「棱镜门」→ 2014 年中央网络安全与信息化领导小组成立、国家集成电路产业投资基金设立、银监会 39 号文 → 2018 年中兴事件与实体清单 → 2020 年进入规模化推广〔证据等级 B，北京通信信息协会《信创发展史及信创相关政策》等多源一致〕。

### 4.2 产业维度：价值链位置与话语权

信创的产业目标不是「造出替代品」，而是改变在标准、架构、生态三层中的位置：

- **标准层**：从遵循国外标准到参与/主导标准（如 RISC-V 国际基金会董事会与 TSC 席位、矩阵扩展标准起草）。
- **架构层**：从指令集授权使用到自主指令集与开源根社区（LoongArch / SW64 / RISC-V / openEuler / OpenHarmony / openGauss）。
- **生态层**：从适配别人的生态到形成可吸引第三方开发的生态（适配条目数、开发者数、ISV 数量）。

### 4.3 经济维度：需求侧牵引

「十五五」规划建议首次把 **「加大政府采购自主创新产品力度」** 写入五年规划，并把「强化企业科技创新主体地位」「支持企业牵头组建创新联合体」与「破除地方保护和市场分割」「消除招标投标、政府采购等方面壁垒」并列〔证据等级 A，gov.cn 全文〕。这组并列表述很重要：政策同时给出**需求侧牵引**与**统一大市场约束**，二者是同一套制度设计的两面，而非相互矛盾。

## 5. 边界与常见误解

### 5.1 信创不等于排斥外资

国办发〔2025〕34 号明确：「国有企业、民营企业、外资企业等各类经营主体平等享受对本国产品的政府采购支持政策」，并禁止「指定品牌或者限制品牌注册地、所有者」「以所有制形式、组织形式、股权结构、投资者国别以及其他不合理条件对供应商实行差别待遇」〔证据等级 A，gov.cn 原文第四条（三）〕。因此把 34 号文解读为「外资出局」是错误的——判断依据是产品是否在关境内完成属性改变、组件成本是否达标，而非供应商国籍。

### 5.2 信创不等于 100% 自研

主流国产操作系统基于 Linux 内核二次开发，主流国产数据库有 PostgreSQL / MySQL / 开源内核衍生路线，云与中间件大量使用开源组件。承认这一点并不削弱信创目标，反而提示真正的评价维度应是：**是否有能力独立维护分支、修复漏洞、演进架构、主导社区**，而不是「是否从零写了全部代码」。行业里「超 90% 商业软件包含开源组件」的判断〔证据等级 C，福建省信创适配中心文章〕也说明，治理重点应落在 SBOM、许可证合规、漏洞响应与供应链透明度上。

### 5.3 国产不等于安全

国产组件同样存在漏洞、勒索、挖矿与供应链污染风险；信创终端的 OS/芯片型号繁杂，反而抬高终端安全的适配门槛〔证据等级 C，行业媒体引述〕。合规上，等保、密评、漏洞管理仍需单独满足。**「替换完成」与「安全达标」是两个独立结论。**

### 5.4 边界争议：该替到什么程度

这是最值得保留的开放问题。一种审慎观点认为：信创初衷是解决**关键基础设施**的卡脖子问题，若把范围无限扩张到充分竞争领域的国企乃至全部办公终端，可能以性能、生态、成本为代价削弱企业市场竞争力；行政订单还可能产生寻租与「马甲」激励〔证据等级 C，行业评论文章，属观点而非事实〕。

与之相对的论述是：规模化应用是技术成熟的必要条件，没有真实负载与反馈就无法完成从「可用」到「好用」的迭代，政策因此采用「2+8+N」分层推进而非一刀切。

本套文档不裁决这一争议，但把它列为理解政策边界的必要视角，并在 [09 风险挑战](./09-风险挑战与批判性视角.md) 中给出正反论点对照。可核查的事实是：「十五五」规划建议同时强调「加大政府采购自主创新产品力度」与「破除地方保护和市场分割」「消除政府采购壁垒」，制度建设的方向是**统一规则下的竞争**，而非无限扩大行政指定范围。

## 6. 八个视角的分析框架

「多视角」不是罗立立场，而是明确每个视角的评价函数不同：

| 视角 | 核心关切 | 成功判据 | 与其他视角的冲突 |
|---|---|---|---|
| **国家 / 安全** | 断供、后门、关基连续性 | 关键领域清单内供给可保障 | 可能牺牲短期效率 |
| **监管 / 合规** | 可核查、可追责 | 声明函、测评公告、等保/密评结论齐备 | 合规成本转嫁给甲方与厂商 |
| **甲方 CIO / 业务** | 业务不中断、体验不降 | TPS/P99 达标、切换窗口可控、可回退 | 与「比例考核」节奏冲突 |
| **架构 / 工程** | 兼容性、可维护性 | 全栈适配清单、回归测试覆盖、多架构构建 | 多路线并存放大适配成本 |
| **厂商 / ISV** | 订单、认证成本、生态位 | 进入采购目录、通过测评、降低重复适配 | 倾向绑定单一路线以降成本 |
| **开发者** | 工具链、文档、社区 | 有对应架构的 JDK/驱动/镜像、问题可搜索 | 国产栈资料少、排障成本高 |
| **采购 / 财务** | TCO、付款节奏、审计 | 全生命周期成本可测、无二次选型 | 低价中标可能诱发降配 |
| **研究 / 投资** | 口径、可比性、周期 | 数据可复现、口径可对齐 | 机构口径差异导致结论相反 |

**使用方法**：任何一条信创相关结论，都应先标明它来自哪个视角。例如「国产化率 85%」在监管视角是成绩，在架构视角只说明采购结构，不能推导系统稳定性；「性能差距 15%—20%」在工程视角可接受，在高频交易视角可能不可接受。

## 7. 四组内在张力

理解信创，本质是理解四组没有一劳永逸解的张力。后续所有文档中的技术选型、政策设计与风险讨论，几乎都能映射到这四组：

1. **安全 vs 效率**：更强的可控性通常意味着更弱的现成生态与更高的迁移成本。
2. **自主 vs 开放**：完全封闭不等于安全，「小而全、弱而全」反而可能降低产业链韧性〔证据等级 B，中国高新网 2025-02-28 引述行业专家观点〕；但过度依赖外部社区又带来治理权风险。
3. **统一 vs 多元**：统一技术路线能降低适配成本，多元路线能避免单点锁定与供应风险；2025 年起按 C86/ARM/自主指令集分标包、每包至少引入多家厂商的做法，正是对这一张力的制度性折中〔证据等级 C，行业转述，需以具体招标文件为准〕。
4. **短期指标 vs 长期能力**：替代比例是短期可测的，根技术能力与生态健康度是长期才可验证的。用前者考核后者，会系统性激励「套壳」与「纸面兼容」。

## 8. 阶段划分（与 02 衔接）

综合多源，产业演进可归纳为五阶段〔证据等级 B/C，不同机构切分年份略有差异，此处取交集〕：

| 阶段 | 时间 | 特征 | 主导驱动力 |
|---|---|---|---|
| 概念奠基 | 2006—2015 | 核高基专项、试点萌芽、安全意识确立 | 科技专项 |
| 试点探索 | 2016—2019 | 信创工委会成立、2+8 体系、党政二期试点 | 政策试点 |
| 全面推广 | 2020—2022 | 信创元年、金融信创生态实验室、79 号文 | 行政推广 |
| 行业深化 | 2023—2025 | 「小信创」转「大信创」、安全可靠测评体系建立、核心系统替换 | 政策 + 合规 |
| 价值替代 | 2025— | 34 号文/十五五/834 号令、AI 融合、从「能用」到「好用」 | 政策 + 市场双轮 |

阶段划分本身也是口径问题：有资料把 2020 称「信创元年」，有资料把 2023 称「大信创元年」，还有把 2026 称「高质量落地元年」。这些标签服务于不同叙事，不宜作为事实引用。可核查的锚点是**政策文号与生效日期**，见 [02](./02-政策脉络与法规体系.md)。

## 9. 本章小结

- 信创是**过程与体系**，不是产品目录；其法定表达分散在政府采购、供应链安全、密码与网络安全等多套制度中。
- 「本国产品」「自主可控」「安全可靠」「等保」「密评」是五套不同的评价逻辑，混用会造成合规判断错误。
- 战略逻辑由安全、产业、经济三条线共同支撑，且「十五五」明确把需求牵引与统一大市场约束并列。
- 边界问题（替到什么程度、是否强制竞争性国企）仍属开放争议，应作为决策背景而非默认前提。
- 后续所有讨论请沿用本文的**八视角框架**与**四组张力**，并在引用数字时遵守 [README 的证据规则](./README.md)。
