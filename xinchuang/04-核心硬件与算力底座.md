## 1. 六家 CPU 厂商、三条技术路线：一张决策级对比表

> 说明：下表「授权性质」「性能定位」综合多源公开资料与厂商公开信息整理〔B/C〕；**具体型号性能以厂商官方规格书与第三方实测为准**，本表不用于性能承诺。

| 厂商 | 指令集 / 架构标识 | 授权与演进路径 | 自主可控程度 | 生态与迁移成本 | 典型场景 |
|---|---|---|---|---|---|
| **海光** | x86 / `x86_64` | 基于 AMD Zen 架构授权，交叉授权模式；进入实体清单后新 IP 获取受限〔C，行业分析〕 | 较低：受 x86 授权与 IP 约束 | **最低**：主流商业软件与内部工具可直接运行，几乎无需重编译 | 金融、电信、政务云，对稳定性与迁移成本敏感的核心系统 |
| **兆芯** | x86 / `x86_64` | x86 授权源自威盛（VIA）体系 | 较低 | 低；桌面与 Windows 生态兼容路线 | 桌面办公、工作站；对既有外设/办公软件依赖强的场景 |
| **鲲鹏 / 海思** | ARMv8 / `aarch64` | ARMv8 指令集永久授权；华为全栈（芯片—OS—DB—云）协同 | 中：受架构版本演进约束 | 中：Linux 开源生态对 aarch64 支持成熟（Nginx/MySQL/Redis/Java/Python/Node.js 均有官方或社区构建） | 数据中心、大数据、分布式存储、云与高并发 |
| **飞腾** | ARMv8 / `aarch64` | ARM 指令集授权；源自国防科大体系，构建 PKS 安全体系 | 中 | 中 | 政务、电力、交通、关基与嵌入式 |
| **龙芯** | **LoongArch** / `loongarch64` | 早期基于 MIPS，后自研 LoongArch 指令集并逐步切换 | **高**：指令集自主定义 | 高：二进制软件需专门适配；已建成 OS、工具链与主流开源软件体系 | 党政办公、工控、教育；对长期可控性要求最高的场景 |
| **申威** | **SW64** / `sw_64` | 源于 Alpha 架构深度改进，发展出自主 SW64 | **高** | 最高：生态最窄 | 超算、特种领域、高性能计算；近年尝试向民用拓展 |

### 1.1 三条技术路线的本质权衡（六家厂商归入其中）

```
                     生态兼容 / 迁移成本  ←────────────→  长期自主可控
 x86 授权  (海光/兆芯)   ●────────────────────────────○     起点高、天花板受授权约束
 ARM 授权  (鲲鹏/飞腾)   ────────●────────────────○         开源生态红利、架构版本风险
 自主指令集(龙芯/申威)   ────────────────●────────●       可控性最强、生态需从零积累
```

- **x86 路线**：把迁移成本降到最低，代价是底层指令集专利与技术演进方向依赖外部授权方；适合存量系统庞大、闭源组件无法重编译的甲方。
- **ARM 路线**：享受 aarch64 的开源软件红利，同时保持较高能效比；代价是指令集版本演进依赖授权链。业界普遍判断国内厂商未获得 ARMv9 永久授权〔C，多家行业分析一致转述，但**非官方确认**，不宜作为确定事实引用〕。
- **自主指令集路线**：长期演进不受外部指令集约束，但需要自建整个软件栈；龙芯近年通过 LoongArch 把 OS、编译器、主流开源软件带起来，申威更集中于超算与特定领域。

### 1.2 选型时真正要问的五个问题

1. 业务依赖的**闭源软件、监控 Agent、数据库驱动、硬件加密组件**是否有对应架构版本？这是 x86→非 x86 迁移中最常见的硬阻塞。
2. 是否存在 C/C++ 本地编译模块、JNI 库、.so 依赖？这些必须按目标架构重新编译。
3. 目标 OS 是否有对应内核版本与驱动支持（尤其 GPU、网卡、RAID/HBA、UKey、打印机、扫码枪）？
4. 供应保障：该型号的量产成熟度、备货周期、迭代路线与售后能力如何？
5. 合规要求：本项目是否要求特定安全可靠测评等级，以及**该等级对应的具体产品型号与公告版本**？

> 工程提示：决策前先执行 `uname -m` 与目标环境验证，确认架构标识。有案例记录团队在未真正切换架构的环境上做了一周「迁移」〔C，技术博客〕。看似基础，但在多架构混合云环境中确实高发。

### 1.3 常见误传辨析

| 说法 | 判定 | 依据 |
|---|---|---|
| 「龙芯后续拓展出 SW-64 指令集，申威基于 Alpha 拓展出 LoongISA」 | **错误，恰好写反** | 龙芯 = LoongArch（早期 MIPS）；申威 = SW64（源于 Alpha）。见 CSDN 文章中出现的错置，与厂商公开资料、架构标识 `loongarch64` / `sw_64` 不符 |
| 「龙芯早期基于 MIPS，因此不算自主」 | 片面 | 判断依据是**当前指令集定义权与持续演进能力**，LoongArch 为自主定义；但历史授权链路仍应在供应链审查中如实披露 |
| 「六大 CPU 都实现了 100% 自主可控」 | 错误 | 三条路线的授权模式与可控程度明显不同，见上表 |
| 「某架构已获得 ARMv9 永久授权」 | 存疑 | 未见官方确认；行业分析普遍作相反判断，引用须标注「业界判断」 |

## 4. 整机、固件与外设：容易被漏掉的层

信创审计中，「全栈国产」的失分点常在整机内部而非 CPU 型号：

| 环节 | 风险点 | 核查要点 |
|---|---|---|
| 电源管理芯片、网络 PHY、时钟、内存接口 | 部分「国产化设备」仅更换主 CPU，关键元器件仍为进口供应链，难以通过高标准审计〔C，工业领域报道〕 | 要求提供 BOM 层级来源与供应链溯源 |
| BIOS / UEFI / BMC | 固件自主程度、远程管理接口、默认口令、漏洞响应 | 固件是否可自主更新、是否有安全启动与度量 |
| 板卡与驱动 | 国产 OS 下驱动缺失或仅提供闭源二进制 | 驱动是否提供目标架构版本、是否有长期维护承诺 |
| 可信计算 | TPCM/TCM 模块、可信度量链 | 是否对接等保与密评要求 |
| 打印机主控芯片 | V3.0 已将其纳入测评对象 | 关注后续公告批次 |
| 工业环境适应 | 宽温、抗振动、电磁兼容、车载/户外/电网工况 | 参数是否匹配实际工况，而非仅看 CPU 型号 |

**结论**：选型时要求供应商提供**端到端适配清单 + BOM 溯源 + 压测报告**，比只看 CPU 品牌更能反映真实国产化程度。

## 5. 上游半导体：全栈可控的现实边界

### 5.1 分层国产化图景（2026 年多源汇总）〔B/C，口径需逐一核对〕

| 环节 | 国产化率 / 状态 | 说明 |
|---|---|---|
| 刻蚀设备 | 50%—65%（与 [03](./03-产业链全景与技术栈.md) §6 统一；部分来源给出 55%—65%） | 成熟制程进展最快 |
| 清洗设备 | 50%—60% | 同上 |
| 薄膜沉积 | 25%—30% | 中等 |
| 光刻机（整体 / 先进制程） | 不足 1% | 最硬约束，EUV 完全依赖海外 |
| 量测、离子注入 | 个位数至低两位数 | 待突破 |
| 材料整体 | 约 15% | 12 英寸大硅片约 10%、高端光刻胶 <10%、电子特气 15%—30%、溅射靶材约 30% |
| EDA 整体 | 12%—20%（与 [03](./03-产业链全景与技术栈.md) §4 统一；早期稿件曾写「全流程 15%—20%」，为区间内较窄口径）；先进制程设计覆盖不足 30%；数字后端 <20%、5nm 以下 <5% | 亦有厂商称「工具覆盖率从不足 30% 提升到 85%」——**覆盖率与国产化率是两个指标，不可混用** |
| 成熟制程（28nm+） | 设备国产化率可达 50%+ | 产能利用率高 |
| 先进制程（7/14nm） | 普遍低于 10% | 良率与成本攻坚中 |
| 先进封装 | 国产化程度最高、追赶最快 | Chiplet、HBM 相关 |
| 全行业人才 | 缺口超 20 万〔C，行业会议引述〕 | 高端研发与技能工匠双重短缺 |

### 5.2 「产量自给率 70%」与「光刻机 <1%」并置

有报告引用高盛数据称中国集成电路**产量自给率**约 70%（2010 年约 38%），同时强调光刻设备是制约完全自主的核心瓶颈〔B，券商转引〕。两者不矛盾：

- 产量自给率衡量的是**芯片颗数 / 产值层面的供给规模**，主要由成熟制程与封测拉动；
- 设备国产化率衡量的是**制造能力的自主程度**，决定先进制程上限。

只引前者会高估可控水平，只引后者会低估产业规模。**正确表述必须成对出现**。

### 5.3 政策与资本

- 大基金三期注册资本 3440 亿元，投向设备、材料、零部件等卡脖子环节〔B/C〕。
- 工信部在 2026 年全国电子信息制造业高质量发展行业会议提出加快促进 RISC-V 产业发展；《电子信息制造业发展「十五五」规划》将 RISC-V 研发与产业化列入任务〔B/C，需以正式发布文本为准〕。
- 「十五五」规划建议把集成电路列为全链条攻关首位领域〔A，gov.cn〕。

## 6. RISC-V：开源路线的机会与约束

### 6.1 可核查进展（2026 年）

| 事项 | 内容 | 证据等级 |
|---|---|---|
| 玄铁系列 | 达摩院公布累计出货突破 60 亿颗；发布车规级处理器；厂商称跑通 Android on RISC-V（**具体版本未见官方适配公告，标「待核实」**） | B/C（峰会报道与厂商官网） |
| 服务器级芯片 | 进迭时空联合香山团队发布 V100，**厂商自称**「业内首颗完整符合服务器全套规范的通用计算芯片」，攻克服务器场景二进制兼容〔**「首颗」为厂商表述，无独立第三方认定，标「待核实」**〕 | B/C |
| 生态共建 | 中国移动、中国电信、中兴、阿里、腾讯等参与香山下一代「昆明湖」架构联合研发 | B/C |
| 标准参与 | 玄铁为 RISC-V 国际基金会高级会员、董事会与 TSC 成员；牵头矩阵扩展标准起草 | B/C（厂商官网） |
| 资本 | 奕斯伟计算登陆港交所成为 RISC-V 赛道首家上市企业；奕行智能完成近 20 亿元融资 | B/C |
| 产业份额 | 有公开演讲转述称 RISC-V 占全球处理器市场约 25% 份额〔**按出货颗数且主要为嵌入式/IoT 口径，不可等同于服务器 CPU 或营收份额；统计年份未披露，标「待核实」**〕 | B/C（公开演讲转述） |

### 6.2 三大约束

1. **产能**：晶圆代工资源向头部倾斜，中小设计企业排产优先级低，出现「手握六万片订单、仅交付两三万片」的现象〔B/C，证券日报报道〕。
2. **扩展碎片化**：各家自定义扩展互不兼容，形成技术「方言」，削弱软件可移植性——这与信创整体面临的碎片化问题同构。
3. **软件生态**：编译器、操作系统、中间件、上层应用对 RISC-V 的支持深度仍不及 aarch64；服务器级落地刚起步。

**判断**：RISC-V 在 IoT、车规、边缘 AI、专用加速等新增场景具备结构性机会；在通用服务器与桌面替代上，中短期内仍是补充路线而非主流替代路线。把它直接列为「第七条信创 CPU 路线」为时过早。

## 7. 硬件选型决策矩阵

| 业务场景 | 优先路线 | 理由 | 主要风险 | 必做验证 |
|---|---|---|---|---|
| 存量核心系统、大量闭源组件无法重编译 | x86 兼容（海光/兆芯） | 迁移成本最低，可沿用既有二进制 | 授权与供应约束 | 驱动与固件完整性、供应链溯源 |
| 新建云原生/大数据平台、以开源栈为主 | ARM（鲲鹏/飞腾） | aarch64 开源生态成熟、多核能效优 | 闭源 Agent/监控组件缺失 | 全量依赖的 aarch64 版本盘点、多架构镜像 |
| 党政办公、工控、对长期可控性要求极高 | 自主指令集（龙芯/申威） | 指令集自主、等级测评表现好 | 专业软件与外设生态 | 逐项软件/外设适配清单、性能基线 |
| 混合存量、多批次采购 | 一云多芯统一纳管 | 屏蔽异构差异、盘活存量资产 | 平台锁定、跨架构调度复杂度 | 镜像可迁移性、故障域隔离、NUMA 性能衰减 |
| AI 训推 / 智算 | 按测评公告 + 生态成熟度 | 2026 年首次纳入安全可靠测评 | 框架/算子/通信库适配 | 模型精度对齐、吞吐与互联带宽实测 |
| 工业现场（宽温、抗振、电磁兼容） | 按工况定，不按 CPU 品牌定 | 现场环境是主要约束 | 参数与工况不匹配 | 环境适应性测试、BOM 溯源、固件自主度 |

## 8. 本章小结

- 六家厂商、三条技术路线构成「迁移成本 × 自主程度 × 演进风险」的三角取舍，**没有全局最优解**；选型的硬约束往往是闭源组件与驱动，而非 CPU 峰值性能。
- 龙芯 = LoongArch、申威 = SW64，网络资料中常见把两者写反；ARMv9 授权状态属业界判断而非官方确认。
- 2026 年第 2 号公告首次把 AI 训推芯片纳入安全可靠测评（9 款，均 Ⅰ 级）；未上榜不代表不合格，测评为自愿申请。
- 整机内部的电源管理芯片、网络 PHY、BIOS/BMC、驱动与打印机主控芯片，是「全栈国产」审计中最常见的失分点。
- 上游半导体的正确图景是「产量自给率约 70%」与「先进制程光刻机不足 1%」并置；EDA、材料、高端 IP 仍是主要约束。
- RISC-V 在新增场景有结构性机会，但产能、扩展碎片化、软件生态三大约束决定其短期是补充路线。
