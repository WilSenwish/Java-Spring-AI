## 1. 五个确定性较高的趋势

> 「确定性较高」指有多源一致的方向性证据或已落地的制度事实；**具体数值预测一律不采信为结论**。

### T1 AI + 信创：从叠加到共生

**制度事实**：《安全可靠测评工作指南 V3.0》（2025-07）把 AI 训练推理芯片纳入测评对象；2026 年第 2 号公告（2026-05-26）首次公布 9 款 AI 芯片结果〔A〕。「十五五」规划建议提出全面实施「人工智能+」行动、强化算力/算法/数据高效供给〔A〕。

**产业方向**：

- 算力侧：智算信创云、超节点、国产 AI 芯片在金融/能源/科研核心行业的规模化落地。
- 终端侧：AI PC 与智能体能力进入国产桌面 OS（如厂商宣传的 Agent OS 形态）〔C，厂商叙事〕。
- 软件侧：大模型与数据库/OS/中间件的智能运维结合（自动调优、慢 SQL 诊断、故障预测）。
- 合规侧：AI 芯片进入测评体系后，采购有了权威选型参考，但**框架/算子/通信库适配**仍是实际瓶颈。

**需要警惕**：AI 叙事容易被用于抬高估值或包装产品，判断落地程度应看「是否有生产级负载 + 精度/吞吐实测 + 关基行业验收」，而非发布会参数。

### T2 云原生与「一云多芯」成为默认架构

多批次采购必然形成 x86 与多种国产架构长期并存，一云多芯从「加分项」变为「基础能力」。判断平台成熟度的四个可测指标：跨架构镜像可迁移性、统一调度与 NUMA 感知、故障域隔离、存量设备纳管与利用率提升。同时必须防范平台锁定（见 [09](./09-风险挑战与批判性视角.md) §6）。

### T3 开源根社区成为技术底座

openEuler、OpenAnolis、OpenHarmony、openGauss、deepin、RISC-V（玄铁/香山）等社区，正在承担「降低重复造轮子、统一适配基线、争取国际标准话语权」三重角色。可观察的标志：运营商与云厂商联合参与下一代开源 CPU 架构研发〔B/C〕；HarmonyOS 进入安全可靠测评并获 Ⅱ 级〔A〕；工信部把 RISC-V 产业化列入「十五五」相关任务〔B/C，**未核对到正式任务文本，标「待核实」，以正式文本为准**〕。

**判断标准**：社区健康度应看代码贡献者、 maintainer 分布、版本节奏、CVE 响应时长、下游商业发行版数量，而不是 Star 数或「生态设备数」。

### T4 根技术攻关成为主战场

「十五五」规划建议把**集成电路、工业母机、高端仪器、基础软件、先进材料**列入全链条攻关清单〔A〕。对应到信创：操作系统内核与文件系统、数据库引擎与分布式事务、编译器与 JIT、EDA 全流程、工业软件内核算法。产业逻辑是「单纯做整机装配、软件集成的企业逐渐被淘汰」〔C，行业观点〕。

**现实边界**：先进制程、EUV、高端光刻胶、高性能 IP 的突破周期以年计，不会因应用侧替代加速而同步解决（见 [04](./04-核心硬件与算力底座.md) §5）。

### T5 从「替代率」到「定义权」

下半场的评价维度正在变化：

| 上半场指标 | 下半场指标 |
|---|---|
| 替代比例、采购完成率 | 商业市场中标率（非行政采购） |
| 适配条目数 | 独立软件数、活跃开发者数、社区贡献度 |
| 入围目录 | 根技术自主度、CVE 响应能力、标准提案数 |
| 能用 | 好用、爱用、TCO 可竞争 |
| 国内替代 | 标准话语权、开源治理权、产品出海 |

有媒体转述称国产分布式数据库落地海外银行核心系统〔C，**未获项目方或一手验收材料核实，标「待核实」**〕；此类个案即便属实也不构成整体竞争力结论，本套文档不将其作为趋势判断依据。

## 2. 制度演进的四个观察点（2026—2030）

1. **34 号文分产品规则陆续落地**：5 年窗口内，财政部会同行业主管部门将分产品确定组件成本占比、关键组件与关键工序要求，并设置 3—5 年过渡期〔A〕。这是未来最值得跟踪的政策变量，直接影响「境内组装」是否继续视同本国产品。
2. **834 号令关键领域清单与调查制度**：清单动态调整、风险监测预警、安全调查与反制措施如何具体实施，将决定关基行业的供应商准入深度。
3. **测评体系继续扩容**：V3.0 已纳入 AI 训推芯片与打印机主控芯片；后续是否纳入更多品类、Ⅰ/Ⅱ 级评判细则是否公开，值得关注。
4. **全国统一大市场约束**：「十五五」明确消除政府采购壁垒、破除地方保护，与地方园区招商、地方准入目录之间的磨合会持续。

## 3. 2027 之后：三个情景

> 情景分析是**推演工具**，不是预测。用途是检验当前决策在不同环境下的稳健性。

| 情景 | 触发条件 | 产业状态 | 对甲方的含义 |
|---|---|---|---|
| **A 乐观：价值驱动** | 根技术持续突破、生态收敛、商业市场中标率上升 | 从「合规采购」转为「性能/成本竞争」，TCO 下降，二次选型风险降低 | 可加快核心系统替换，议价空间增大 |
| **B 基准：双轨长期化** | 替代目标完成但生态与性能差距仍在，多架构并存 | 一云多芯常态化；适配与重测成为固定运维成本；政策与市场双轮 | 按 5 年 TCO 规划，保留回退与多供应商 |
| **C 审慎：质量返工** | 伪自主被集中追责、证书过期引发二次选型、性能问题在生产暴露 | 部分项目重建、预算追加、供应商洗牌 | 合同中的持续合规与免费重测条款价值凸显 |

**稳健策略**：按情景 B 做预算与架构，用情景 A 的期权（保留可迁移性）参与上行，用情景 C 的防线（证书台账、源码/二进制抽检、回退能力）控制下行。

## 4. 分角色决策建议

### 4.1 甲方 CIO / 架构师

1. **先定口径再定方案**：明确本项目属于关基与否、合规包清单、可接受的性能阈值与 TCO 模型。
2. **收敛组合**：应用侧只支持 1—2 套主流 CPU+OS+DB 组合，异构差异交给云平台。
3. **把版本写进资产台账**：每个适配结论绑定架构、OS 内核版本、DB 版本；变更触发重测。
4. **保留可迁移性**：数据格式、镜像、API、配置外置（见 [07](./07-行业落地与工程迁移方法论.md) §5.3）。
5. **验收看生产级证据**：长稳压测、故障注入、字段级比对、回退演练记录，而非适配清单数量。

### 4.2 采购 / 合规

1. 技术规格写**性能指标 + 测评等级 + 公告批次 + 有效期**，不写品牌但要求投标型号与到货一致。
2. 严格按 34 号文：不得指定品牌、不得按所有制或投资者国别设限；要求声明函并随中标结果公告。
3. 区分四套体系：等保、密评、安全可靠测评、适配报告各要各的材料（见 [06](./06-安全合规与测评认证体系.md) §1、§7）。
4. 建立**证书到期台账**（三年有效期）与年度等保/密评日历。
5. 合同写入持续合规、免费重测与适配、禁止降配、SBOM 交付条款。

### 4.3 ISV / 厂商

1. 用「依赖矩阵 + 版本矩阵」管理适配，而非一次性拿证；把回归测试流水线化。
2. 优先支持 1—2 套组合并做深（性能级适配），而不是广撒网做纸面兼容。
3. 主动披露供应链：SBOM、开源许可证清单、自主补丁记录、漏洞响应 SLA——这是未来审计的重点。
4. 把「三年有效期」纳入产品路线，避免客户被迫二次选型。
5. 差异化定位：底层拼根技术与社区，中层拼迁移工具链与案例，上层拼行业 Know-how。

### 4.4 开发者 / 技术团队

1. 掌握**目标架构标识**（`x86_64` / `aarch64` / `loongarch64` / `sw_64`）与多架构构建。
2. 把配置外置、避免硬编码路径与方言；SQL 尽量走标准写法，分页交给方言层。
3. 建立「适配问题清单」知识库，记录现象、定位、方案、回归结果。
4. 主动补齐国密、密评、SBOM 等合规相关工程能力——这些是信创项目的固定工作包。
5. 按 [07](./07-行业落地与工程迁移方法论.md) §5.9 的 20 项验收清单做自查。

### 4.5 研究者 / 分析人员

1. 任何规模、渗透率、份额数字绑定「机构 + 报告 + 年份 + 口径 + 实绩/预测」。
2. 跨口径数字只用于方向判断，不计算增速、份额、CAGR。
3. 引用政策前核对原文与施行日期；对 79 号文等未公开全文的文件标注「转述」。
4. 优先使用 [附录](./APPENDIX-参考资料与术语表.md) 中 A 级来源做事实锚点。

### 4.6 投资者

> 本节仅描述分析框架，**不构成任何投资建议**。

关注点应是：商业市场（非行政采购）收入占比、迁移工具链与服务的复利效应、根技术与社区参与度、证书与产品迭代的同步率、回款质量；警惕以「适配条目数」「生态设备数」「远期市场规模预测」为核心的叙事。

## 5. 选型决策矩阵（汇总版）

| 场景 | 推荐路线 | 关键理由 | 主要风险 | 必做验证 |
|---|---|---|---|---|
| 存量核心、闭源组件多 | x86 兼容（海光/兆芯） | 迁移成本最低 | 授权与供应约束 | 驱动/BOM 溯源、供应链审查 |
| 新建云原生、开源栈为主 | ARM（鲲鹏/飞腾）+ openEuler 系 | 生态成熟、能效优 | 闭源 Agent 缺失 | 全依赖 aarch64 版本盘点、多架构镜像 |
| 党政办公 / 工控 / 长期可控 | 自主指令集（龙芯/申威） | 指令集自主 | 专业软件与外设生态 | 逐项软件与外设适配清单 |
| 多批次混合采购 | 一云多芯统一纳管 | 屏蔽异构、盘活存量 | 平台锁定 | 镜像可迁移、API 开放、故障域隔离 |
| Oracle 存量重的业务系统 | 高 Oracle 兼容集中式库 | 兼容模式覆盖大部分 SQL | 剩余 30% 人工改写 | 全量 SQL 扫描、双轨比对、执行计划重调 |
| 高并发核心交易 | 分布式事务型库（按案例选型） | 已有银行/运营商核心案例 | 分片与运维复杂度 | RPO/RTO、故障切换演练、跑批窗口 |
| 高风险不可停业务 | 双轨并行 + 灰度切换 | 秒级回退能力 | 双轨周期成本 | 字段级比对、回退演练 |
| AI 训推 / 智算 | 测评公告内产品 + 生态成熟度 | 2026 起有权威选型参考 | 框架/算子/互联适配 | 精度对齐、吞吐与带宽实测 |

## 6. 90 天行动计划模板（甲方）

> **阶段口径**：下表 W1—W13 是 [07](./07-行业落地与工程迁移方法论.md) §3 **S0—S5 唯一主表的周计划时间展开**，不是另一套阶段命名：W1—W4 ≈ S0/S1，W5—W10 ≈ S1/S2，W11—W12 ≈ S3，W13 ≈ S4/S5。门禁以 §3 定义为准。

| 周次 | 动作 | 产出 | 门禁 |
|---|---|---|---|
| W1—W2 | 资产与依赖盘点、合规基线判定、业务性能基线签署 | 资产台账、依赖矩阵、合规矩阵、性能基线 | 无硬阻塞依赖 |
| W3—W4 | 确定 1—2 套目标组合；搭建 1:1 测试环境；确认闭源组件版本 | 组合方案、环境验收记录 | 环境 1:1、架构标识正确 |
| W5—W8 | 冒烟 + 核心流程跑通；建立适配问题清单；完成 SQL 扫描与 JDK/驱动组合压测 | 适配问题清单、性能对比报告 | 性能达合同约定阈值 |
| W9—W10 | 代码/SQL 改造、多架构镜像与 CI、国密改造设计、密码应用方案评估 | 改造包、多架构流水线、密评方案结论 | 回归通过、方案通过评估 |
| W11—W12 | 全量+增量数据迁移演练、双轨并行启动、字段级比对、回退脚本演练 | 迁移方案、比对报告、回退演练记录 | 差异归零、回退成功 |
| W13 | 灰度切换决策评审；等保/密评（运行前）准备；验收材料预审 | 切换方案、合规包预审意见 | 全部门禁通过 |

> 周期仅为模板，实际工期由存量 SQL 规模、闭源组件数量与双轨周期决定；核心系统案例显示全栈建设周期可达数百天（见 [07](./07-行业落地与工程迁移方法论.md) §2）。

## 7. 能力自查清单（组织级）

| 能力 | 达标标志 |
|---|---|
| 口径治理 | 所有对外数字绑定机构/年份/口径；无跨口径计算 |
| 依赖治理 | 有全量依赖矩阵与 SBOM；闭源组件目标架构版本有书面确认 |
| 版本治理 | 有 CPU×OS×DB×中间件版本矩阵；变更触发重测机制 |
| 合规治理 | 四套体系材料齐备；证书到期台账；年度等保/密评日历 |
| 工程治理 | 1:1 环境、双轨并行、字段级比对、回退演练为强制门禁 |
| 供应链治理 | BOM/SBOM 溯源、供应商安全协议、多元供应渠道、开源许可证治理 |
| 人才治理 | 适配问题清单知识库、运维培训记录、架构师梯队 |
| 商业治理 | 5 年 TCO 模型、可迁移性条款、禁止降配与免费重测条款 |

## 8. 结语：三道坎

信创产业必须依次跨过三道坎：

1. **有没有** —— 产品与供给是否存在（基本已跨过）。
2. **好不好** —— 性能、生态、体验、TCO 是否可与成熟栈竞争（正在跨）。
3. **强不强** —— 是否具备根技术原创能力、标准话语权与开放生态吸引力（尚未跨过）。

第三道坎决定了「替代」最终是终点还是起点。对具体组织而言，最务实的做法不是预测产业何时跨过，而是**把自己的架构做成可迁移、可验证、可回退的**——这样无论产业走到哪一步，决策都保留选择权。

## 9. 本章小结

- 五个方向性趋势：AI+信创、一云多芯常态化、开源根社区成为底座、根技术攻坚、从替代率转向定义权。
- 2026—2030 最值得跟踪的制度变量是 34 号文分产品规则、834 号令关键领域清单、测评品类扩容与全国统一大市场约束。
- 用三情景推演检验决策稳健性：按「双轨长期化」做预算，保留上行期权与下行防线。
- 分角色给出可执行清单；甲方 90 天计划与组织级 8 项能力自查可直接落地。
- 结语的「三道坎」是判断产业阶段最简洁的框架，也是本套文档的收束。
