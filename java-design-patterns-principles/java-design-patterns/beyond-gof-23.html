01创建型延伸 Creational extensions

对象「怎么生、生命周期怎么管」——GoF 之外围绕工厂变体、依赖装配、池化与懒加载展开的 10 个模式。

C1抽象文档abstract-document

核心意图：用键值对动态承载对象属性，避免为每种文档建子类。

适用场景 · 文档结构多变、需运行时增删字段时。

关联：与 桥接 / 组合 共享『动态结构』思路。

C2依赖注入dependency-injection

核心意图：由容器在运行时把依赖装配进对象，调用方不自己 new。

适用场景 · 需解耦高层与底层、便于测试替换依赖时。

关联：创建型终点，落实 依赖倒置 DIP。

C3工厂factory

核心意图：用统一工厂方法封装对象创建，向调用方隐藏具体类型。

适用场景 · 创建逻辑集中、产品类型易变时。

关联：工厂方法 的轻量变体。

C4工厂套件factory-kit

核心意图：用枚举 + lambda 注册一批工厂，按需取用。

适用场景 · 产品族较多且创建方式相似时。

关联：抽象工厂 的紧凑实现。

C5懒加载lazy-loading

核心意图：真正用到时才创建或取值，延迟昂贵操作。

适用场景 · 大对象、远程资源、图片等按需加载。

关联：与 虚拟代理 同思路。

C6单态monostate

核心意图：多实例共享同一静态状态，对外表现得像多个对象。

适用场景 · 需要『逻辑单例』但不想限制实例数量时。

关联：单例 的变体。

C7多例multiton

核心意图：按 key 维护一组受控命名实例（如枚举实例）。

适用场景 · 需少量命名且受控的实例集合时。

关联：单例 按 key 泛化。

C8对象池object-pool

核心意图：复用昂贵对象（连接/线程），避免反复创建与销毁。

适用场景 · 资源创建成本高、并发借还频繁时。

关联：与 线程池 同源。

C9步骤建造者step-builder

核心意图：用流式、类型安全的 API 分步构造复杂对象。

适用场景 · 构造参数多、部分必填且需校验时。

关联：建造者 的类型安全进化。

C10DAO 工厂dao-factory

核心意图：按数据源类型创建对应的数据访问对象。

适用场景 · 多数据源 / 多 ORM 切换场景。

关联：抽象工厂 在持久层落地。

02结构型延伸 Structural extensions

对象『怎么拼成更大结构』——在 GoF 七结构模式之外，关于视图组合、转换、转发与代理进化的 10 个模式。

S1复合视图composite-view

核心意图：把页面拆成可复用的子视图再组合渲染。

适用场景 · Web 页面由多个组件拼装时。

关联：组合 在视图层的落地。

S2组合实体composite-entity

核心意图：把一组相关实体作为整体持久化 / 传输。

适用场景 · 聚合根跨多表一致性场景。

关联：组合 + 实体。

S3转换器converter

核心意图：在两层模型间做一对一字段映射（如 DO↔DTO）。

适用场景 · 分层间对象转换、避免手工 getter/setter。

关联：适配器 的专用化。

S4委托delegation

核心意图：把请求转发给另一个对象处理，自身只做转发。

适用场景 · 复用他者能力而不继承时。

关联：与 代理 / 装饰器 共享转发思路；落实 组合优于继承。

S5前端控制器front-controller

核心意图：用单一入口统一处理请求（路由 / 视图分发）。

适用场景 · Web 框架的请求总入口。

关联：与 服务层 / 拦截过滤器 协作。

S6标记接口marker-interface

核心意图：用空接口给类打『标签』供框架识别。

适用场景 · 序列化 / 可克隆等元数据标记。

关联：现代多被 注解 取代。

S7私有类数据private-class-data

核心意图：把可变字段封装进内部对象，限制外部修改。

适用场景 · 保护对象内部状态不被误改时。

关联：与 封装 / 不可变 同源。

S8孪生twin

核心意图：用两个协作对象表达『多继承』语义（Java 无多继承）。

适用场景 · 需复用两个不相关类的行为时。

关联：桥接 的特例。

S9虚拟代理virtual-proxy

核心意图：延迟加载真实对象，代理先占位。

适用场景 · 大图 / 远程对象按需加载。

关联：代理 的懒加载分支；与 懒加载 同源。

S10动态代理dynamic-proxy

核心意图：运行时生成代理类统一拦截方法调用。

适用场景 · AOP、统一日志 / 事务 / 鉴权。

关联：代理 + 反射；Spring AOP 基石。

03行为型延伸 Behavioral extensions

职责与沟通归谁——GoF 十一行为模式之外的回调、函数式行为、空对象与访问者去环等 12 个模式。

B1回调callback

核心意图：把『完成后做什么』作为参数传入，异步通知。

适用场景 · 异步任务完成后的处理。

关联：与 观察者 / 命令 同源（策略式传递行为）。

B2集合管线collection-pipeline

核心意图：用 map / filter / reduce 链式处理集合。

适用场景 · 集合批量变换，替代显式循环。

关联：迭代器 + 策略 的函数式合流。

B3指令器commander

核心意图：封装一组命令并统一调度（类似宏）。

适用场景 · 需要组合 / 批量执行操作时。

关联：命令 的批量形态。

B4组合子combinator

核心意图：用小函数组合出更复杂函数（解析 / 校验）。

适用场景 · 可组合的解析或校验逻辑。

关联：与 函数组合 同源。

B5柯里化currying

核心意图：把多参函数变成依次接收单参的函数序列。

适用场景 · 参数复用、偏函数场景。

关联：函数式基础，弱化 策略 必要。

B6流畅接口fluent-interface

核心意图：方法返回 this 形成链式调用。

适用场景 · DSL、构建器风格 API。

关联：与 建造者 同源。

B7函数组合function-composition

核心意图：把多个函数串成管道 f∘g∘h。

适用场景 · 数据变换流水线。

关联：与 集合管线 / 组合子 同源。

B8空对象null-object

核心意图：用无行为对象替代 null，消除空判断。

适用场景 · 缺省行为、避免 NPE。

关联：与 特殊情形 / 策略 同源。

B9仆人servant

核心意图：把一组类共有的操作抽成独立服务类。

适用场景 · 多类共享功能却不愿塞进基类时。

关联：与 委托 同源。

B10规格specification

核心意图：把业务规则封装为可组合的判断对象。

适用场景 · 复杂条件组合查询。

关联：与 策略 / 组合 同源；对应 组合优于继承。

B11蹦床trampoline

核心意图：把递归转成循环 + 暂停，避免栈溢出。

适用场景 · 深递归 / 尾调用优化。

关联：与 迭代器 思路（控制流外提）。

B12无环访问者acyclic-visitor

核心意图：用泛型避免访问者对结构类的反向依赖环。

适用场景 · 需多操作又不污染结构类时。

关联：访问者 的去环变体。

04并发与线程级 Concurrency & Threading

当系统里有多个执行流——如何让它们不互相踩踏。这是 GoF 诞生时尚不存在（或未被命名）的一条长尾，共 21 个模式。

图 4 · 并发与线程级 主线示意图。

C1活动对象active-object

核心意图：把方法调用转成消息，串行化到专属线程执行。

方法调用被封装成消息入队，由专属线程串行执行；把并发隐藏在对象身后。

适用场景 · 把并发隐藏在对象身后时。

关联：与 命令 / 消息队列 同源。

C2异步方法调用async-method-invocation

核心意图：立即返回 Future，结果稍后取。

立即返回 Future 占位，计算在别处进行；稍后通过 Future 取真实结果，不阻塞调用方。

适用场景 · 不阻塞等待的远程 / 重计算。

关联：与 承诺 / Future 同源。

C3背压backpressure

核心意图：下游慢时反向通知上游限流。

适用场景 · 流处理 / 响应式管线。

关联：与 生产者-消费者 协作；落实 节流。

C4拒绝balking

核心意图：对象状态不合适时直接拒绝请求而非等待。

适用场景 · 初始化未完成 / 资源未就绪时的保护。

关联：与 守卫暂停 对照（不等待）。

C5双重检查锁double-checked-locking

核心意图：懒加载单例的并发安全写法。

适用场景 · 延迟初始化且高并发。

关联：单例 的并发坑；警示 可见性。

C6分治并行fork-join

核心意图：把任务拆成子树、结果合并。

适用场景 · 可递归分解的并行计算。

关联：与 map-reduce 同源（分治）。

C7守卫暂停guarded-suspension

核心意图：条件不满足时线程等待直至满足。

适用场景 · 需等待特定状态再继续。

关联：与 拒绝 对照（等待）。

C8半同步半异步half-sync-half-async

核心意图：异步层收请求、同步层处理，解耦两者。

适用场景 · 高并发服务（如网络框架）。

关联：与 反应器 协作。

C9领导者选举leader-election

核心意图：多副本中选一个主导者避免脑裂。

适用场景 · 分布式主从 / 协调。

关联：与 微服务自注册 协作；落实 共识。

C10领导者-跟随者leader-followers

核心意图：一组线程选一个等事件、其余待命。

适用场景 · 高吞吐事件处理。

关联：与 线程池 对照（省上下文切换）。

C11可锁对象lockable-object

核心意图：把锁与数据封装在一起避免忘解锁。

适用场景 · 需显式锁的共享数据。

关联：与 RAII / 资源获取即初始化 同源。

C12映射归约map-reduce

核心意图：分片 map 后 shuffle-reduce。

适用场景 · 海量数据批处理。

关联：分治；与 fork-join 同源。

C13监视器monitor

核心意图：用互斥 + 条件变量封装线程协作。

适用场景 · 经典管程同步。

关联：与 守卫暂停 同源（语言级同步原语）。

C14乐观离线锁optimistic-offline-lock

核心意图：用版本号检测并发冲突而非长事务。

适用场景 · 长会话 / 离线编辑。

关联：与 版本号 / Unit of Work 协作。

C15毒丸poison-pill

核心意图：用特殊消息通知消费者优雅退出。

适用场景 · 关闭线程池 / 处理管线。

关联：与 生产者-消费者 协作。

C16轮询发布polling-publisher

核心意图：定期拉取变更再推送，降低实时推送压力。

适用场景 · 变更不频繁的通知。

关联：与 发布-订阅 对照（拉 vs 推）。

C17生产者-消费者producer-consumer

核心意图：用队列解耦生产与消费速率。

生产者和消费者通过有界阻塞队列解耦，队列满/空时自动背压，平衡速率。

适用场景 · 任务 / 消息缓冲。

关联：背压 / 队列限流 的基石。

C18承诺promise

核心意图：代表未来结果的占位对象，可链式编排。

适用场景 · 异步结果编排。

关联：与 Future / 回调 同源。

C19反应器reactor

核心意图：事件循环 + 非阻塞处理，单线程扛高并发。

Reactor 事件循环接收事件，Dispatcher 分发给对应 EventHandler；单线程串行处理避免锁。

适用场景 · 高并发 I/O（Netty / Reactor）。

关联：与 半同步半异步 对照。

C20线程池thread-pool-executor

核心意图：复用固定线程、限流提交。

ThreadPool 复用固定 Worker，Client 提交 Task；避免反复创建线程，控制并发度。

适用场景 · 大量短任务。

关联：对象池 在线程上的落地。

C21线程局部存储thread-specific-storage

核心意图：每线程独享一份变量（ThreadLocal）。

适用场景 · 跨方法透传上下文（事务 / 用户）。

关联：与 单例 对照（按线程隔离）。

05架构级 Architectural

把系统本身当成设计对象——代码怎么分层、服务怎么切、UI 怎么组织。共 41 个模式，是 1994 年之后增长最猛的一条尾巴。

图 5 · 架构级 主线示意图。

A1MVCmodel-view-controller

核心意图：模型-视图-控制器分离关注。

适用场景 · 传统 Web / 桌面 UI。

关联：与 关注点分离。

A2MVPmodel-view-presenter

核心意图：用 Presenter 隔离 View 与 Model，便于测试。

适用场景 · 需可测 UI。

关联：MVC 的测试向进化。

A3MVVMmodel-view-viewmodel

核心意图：ViewModel 用数据绑定驱动 View。

适用场景 · WPF / 前端数据绑定。

关联：观察者 + 数据绑定。

A4MVImodel-view-intent

核心意图：单向数据流，Intent→Model→View。

适用场景 · 响应式前端（如 Android）。

关联：与 单向数据流 / Redux 同源。

A5分层架构layered-architecture

核心意图：按层（表现 / 业务 / 持久）隔离。

依赖严格向下；上层调用下层，下层不反向依赖，形成单向依赖链。

适用场景 · 传统企业应用。

关联：与 关注点分离 / 单一职责。

A6六边形架构hexagonal-architecture

核心意图：端口 + 适配器，业务居中、外围可换。

应用核心居中，左端口接驱动适配器、右端口接被驱动适配器；内外通过端口解耦。

适用场景 · 需易替换基础设施。

关联：落实 依赖倒置 DIP / 接口隔离 ISP。

A7整洁架构clean-architecture

核心意图：依赖指向内层实体，外层可换。

依赖指向圆心：外层（框架/适配器）依赖内层（用例/实体），内层不感知外层。

适用场景 · 长期演进业务系统。

关联：与 六边形 同源；落实 DIP。

A8洋葱架构onion-architecture

核心意图：同心圆分层，依赖向内。

适用场景 · 与整洁架构等价表述。

关联：整洁架构 的变体。

A9单体架构monolithic-architecture

核心意图：单进程部署所有模块。

适用场景 · 早期 / 小型系统。

关联：与 微服务 对照（演进两端）。

A10事件驱动架构event-driven-architecture

核心意图：用事件解耦生产者与消费者。

适用场景 · 松耦合异步系统。

关联：与 观察者 / 发布订阅 / 事件溯源 协作。

A11事件溯源event-sourcing

核心意图：用事件序列而非当前状态存储。

状态不存当前值而存历史事件序列；重建即重放事件，可审计、可回放时间点。

适用场景 · 审计 / 回放 / 时序系统。

关联：与 CQRS 常搭档；落实 不可变。

A12CQRScommand-query-responsibility-segregation

核心意图：读写模型分离各自优化。

适用场景 · 读写负载差异大。

关联：命令查询分离 CQS 的架构放大。

A13Sagasaga

核心意图：把分布式事务拆成本地事务 + 补偿。

分布式事务拆成本地步骤序列，每步含补偿；失败按逆序补偿，达成最终一致。

适用场景 · 跨微服务一致性。

关联：与 事务性发件箱 协作；落实 最终一致。

A14BFFbackends-for-frontends

核心意图：为不同前端定制聚合后端。

适用场景 · 多端（Web / App）聚合。

关联：与 API 网关 / 聚合器 协作。

A15断路器circuit-breaker

核心意图：失败率超阈即跳闸快速失败。

适用场景 · 防下游故障拖垮调用方。

关联：对 墨菲定律 的工程回应。

A16客户端会话client-session

核心意图：把会话状态放客户端，服务端无状态。

M1AAA 三段式arrange-act-assert

核心意图：测试分『准备-执行-断言』三段。

适用场景 · 可读单测。

关联：与 对象母亲 协作（测试）。

M2页面对象page-object

核心意图：把页面元素 / 操作封装成对象。

适用场景 · UI 自动化测试。

关联：与 表示模型 / 视图助手 同源。

M3裸对象naked-objects

核心意图：直接把领域对象当 UI。

适用场景 · 快速 CRUD 应用。

关联：与 领域模型 极端化。

M4组件component

核心意图：自包含可复用 UI / 功能单元。

适用场景 · 前端 / UI 组合。

关联：与 组合 / 视图 同源。

M5子类沙箱subclass-sandbox

核心意图：用基类限制子类能力（安全）。

适用场景 · 插件 / 脚本沙箱。

关联：与 模板方法 / 委托 同源。

M6Blocbloc

核心意图：用事件→状态流管理 UI 状态。

适用场景 · 前端状态管理。

关联：与 MVI / 单向数据流 同源。

M7Fluxflux

核心意图：单向数据流（Action→Dispatcher→Store）。

适用场景 · 前端状态。

关联：与 Redux / MVI 同源。

M8规则引擎rule-engine

核心意图：把业务规则外置为可执行规则。

适用场景 · 多变业务策略。

关联：与 策略 / 规格 同源。

M9特性开关feature-toggle

核心意图：用开关控制功能发布。

适用场景 · 渐进发布 / AB。

关联：与 策略 同源（运行时分支）。

M10收集参数collecting-parameter

核心意图：用对象累积多步结果返回。

适用场景 · 多步收集。

关联：与 参数对象 同源。

M11管线pipeline

核心意图：把处理步骤串成管道。

适用场景 · 数据处理流。

关联：与 集合管线 / 责任链 同源。

M12宽容读取tolerant-reader

核心意图：忽略未知字段稳健解析。

适用场景 · 跨版本集成。

关联：与 防腐层 / 适配器 同源。
